## Warm unknown, retry and cold restart

Warm unknown freezes writes. Retain the original whole operation/pending checkpoint/ID and actual ticket, source/target/head observation, complete before/target/resource union, past/future/pending/export obligations and actual encoded/appearance/geometry leases with unverified debt. Probe/reconcile through existing authority.recover/codec.inspectRecovery with that same original ID and exact operation/receipt digest. Never call prepare, replay commands, allocate a replacement ticket, change target/Expected or collect blobs to resolve unknown. A matching committed receipt accepts the ORIGINAL ticket once and promotes the exact target; an original not-written/not-committed determination rejects that ticket and keeps source/redo. Divergent receipt/checkpoint stays unresolved and frozen; a guessed boolean or matching ID alone is insufficient.

Before Apply, a verified refusal/capacity failure can start a NEW user attempt from a fresh source/ID after cleanup; it cannot be called a same-ID retry. During an unconfirmed CAS, only original outcome reconciliation is allowed. After confirmed commit, native promotion/rebuild failure becomes presentation-error with the committed document intact. RetryPresentation constructs presentation for that committed target only, with fresh actual epochs/capacity/ledger. It cannot reapply geometry, alter marks, refund resources, reject an already accepted ticket or roll back confirmed storage. Unverified retirement remains charged until the provider supplies a verified receipt.

Cold boot has NO valid old GPU/resource capabilities or live history ticket. Reopen and validate the existing persisted checkpoint/pending/whole receipt and reconcile original ID/outcome BEFORE new decoder/native preparation. This is a proposed combined boot ordering requirement, not a claim that current C1 boot already implements it. Do not manufacture an edit/public repair or substitute a new ID. Match exact pending/receipt/full settled checkpoint through the existing codec; divergence stays frozen. Committed chooses the exact recorded target, not-committed the exact before document. Only then open/rebuild presentation with fresh actual leases/epochs. Missing encoded bytes leave explicit resource/presentation unready; do not replace artwork, refill anything or replay the original operation.

The current persisted format does NOT contain volatile undo/redo topology. After cold settlement, initialize the existing session journal using its existing beginOpen/accept path ONCE (ad41 session.js:84). Its past/future stacks are honestly reset. This does NOT reset durable journal/receipts/operation IDs, rewrite the recovered target or pretend the lost undo ticket survived. Durable preservation of the old undo/redo topology would require a separately versioned history persistence/migration decision; it is not silently promised by this proposal.

Before cold retention/GC decisions, derive known resource obligations from full current/before/target, pending and retained receipt documents plus known durable encoded/export retention records. Old in-memory obligations whose survival cannot be proven are UNRESOLVED, never assumed empty or safe to collect. No blob GC while outcome/obligation closure is uncertain. A fresh presentation failure does not erase this debt or reopen outcome ambiguity.

## Design choice for map authoring

Accuracy: actual-public-result-first preserves the accepted geometry algorithm's exact result instead of introducing a predictor. Exact historical data preserves authored cause and effect; this is software correctness evidence, not a physical realism measurement. Prefer it for Nautilus map authoring across all three consumers, pending their explicit capability review.

Efficiency: one resource-free public prepare and one final native candidate avoid duplicated geometry evaluation and an intermediate native view by construction. This is a code-based cost estimate, not a frame-rate, decoder or device measurement. Read-only history observation avoids early ticket churn; full validation and retained debt still cost work/memory. Measure representative native scenes before performance claims.

Narrative: atomic placement of geometry and its local graphics, followed by exact Undo/Redo, preserves the map author's intended appearance (subjective experience judgment). Prefer this over temporarily exposing an unpainted placement or restoring a generic preset. Preserve existing profiles for compatibility; no game is integrated merely because this proposal names it. Adoption remains deferred until Architect acceptance and actual native/visual evidence.
