## One-use target-to-acquisition association

The existing views manager receives a bundle and room/currentness callback. That geometry alone does not identify the complete authoring target, artwork projection or appearance choice. A source-unchanged edit can retain exactly the same bundle while changing appearance. The Artist provider must receive the actual same-attempt prepared target through an opaque one-use association, not infer it from UVs or read a mutable `lastDocument`.

The actual phase owner should mint `PreparedTargetAssociation` only after its source, target document, projection and choice are authenticated, while the attempt is current. It binds exact attempt/work, source generation, target reference and digests, selected phase/provider, and original context. Its private WeakMap owns these fields; callers receive no data-shaped mint/restore method. No resource or work credit is created by this carrier.

The Kernel's actual `scope.native.acquireCandidate` must carry that association through the **same** views-manager job to the actual `presentation.acquire(bundle,room/current)` callback. This requires an explicitly reviewed ephemeral job carrier (for example, a C2-only optional acquisition argument passed through `views.acquire` and the resulting `acquire` call). A synchronous ambient frame cannot safely span the manager's queued promise. A map keyed only by bundle identity is insufficient for late/repeated acquisitions with unchanged geometry. Root/Native should freeze the precise carrier change and preimages before implementation; no such shared views change is applied here.

The provider consumes the exact association once for that actual job, proves same attempt/work/source/context and target, and returns a candidate that the same manager owns. Final `bindActualManagerCandidate` checks the actual manager record is paired with that consumed association. Cancellation, queued replacement, disposal or late delivery invalidate the association and retire only its actual owned candidate; uncertain cleanup stays charged. Caller flags, copied association DTOs and a candidate from another manager/provider refuse.

The Artist's owned floor/inspection/bounds/picking/resize APIs remain the sole controls for its sealed objects. Do not reuse C1 direct child `.visible` edits or mutate other sealed native children behind those APIs. This plan creates no second manager, presentation cache, authority, service, planner or history.
