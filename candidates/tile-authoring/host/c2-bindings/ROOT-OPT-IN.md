# Required Root profile opt-in

The actual entry `apps/editor/tile-authoring/session.js` builds a frozen C1 profile and passes only that profile to `createSmartTileSession`. Supplying top-level `c2Host` / `c2PhasePorts` is ignored by that private Kernel: it reads those fields from the profile. A complete private composition must therefore happen before the one smart-session call.

`root-session-opt-in.patch` records a proposed separate Root semantic adaptation against the exact Main1e wrapper. Its final private Host import path is proposed, not an existing ready file. Root must deliberately assign/promote that path and authenticate its source. The candidate's `composeSameSessionC2Profile` currently refuses every call because no actual production composition has been minted. The patch is not applied here or in Root and does not assert that the wrapper is bound.

The eventual reviewed Host factory must mint `privateC2Composition` in its own private WeakMap after it authenticates the same executable Core coordinator/registry/continued validator, actual Editor observer/resource facts, actual Artist phase/native owner, actual codec, bootstrap and connection. The composer must reject copies, foreign pairings and stale owner lifetimes. Caller callbacks, shape checks, `isBound:true`, digests and static587 types cannot create this capability. A source-auth record must name the accepted composition implementation and this semantic change separately from literal relocations.

The composer creates one frozen profile preserving every original C1 function and guard, except for the explicitly composed `authoringSnapshot` witness wrapper and the two private fields `c2Host` / `c2PhasePorts`. The phase record stays the Kernel's closed four-field interface. Native replacement/retention goes through the presentation ports passed to this same session. Host must not call `createSmartTileViews`, create another session or acquire another independent manager. The existing Kernel creates the sole views manager, routes its acquisition capability to the phase, owns the actual ticket/WAL/CAS, and performs actual journal acceptance.

Bootstrap observation begins in the outer real constructor before binding/codec/source construction. This wrapper cannot retroactively count it. Its input `binding` and the composition must refer to that exact already-begun bootstrap. Source read registration likewise begins its actual readonly purpose before calling the real workbench. The private read frame observes `original.authoringSnapshot`'s real codec-owned checkpoint before Kernel clones its output, but it registers only the exact final `workbench.getSnapshot()` return after final context/connection checks. Ordinary subscriptions and copied snapshots do not register. The existing service/workbench factory remains responsible for actual private service/session membership.

Current fixed4ade tests exercise the exact private Kernel with its explicit test-only profile-composition setup adapter, real C1 profile, real public Core, actual workbench/service and Node Three geometry. This is evidence for composition mechanics and exact read tagging, not proof that Root's ordinary wrapper already selects C2 or that a real meter/SourceRegistry/Native phase is available. The test-only observer must never be promoted as a production pairing.

The other required Kernel change remains `kernel-4ade-begin-control.patch`. `beginPrepare` must receive `{action,draft,lockId}` references, so the actual already-owned edit request ID (or one existing history ID) is known before paid ingress copies. This opt-in patch does not replace or hide that separate adaptation.

`CONSTRUCTION-AND-ACQUISITION.md` records the additional exact live-journal registration and one-use target association gaps. `kernel-single-journal.patch` is a proposed original-construction change, pending the fixed executable Core factory. The original single views manager also needs an explicit association carrier frozen with Native; no ambient target or second manager is a substitute.
