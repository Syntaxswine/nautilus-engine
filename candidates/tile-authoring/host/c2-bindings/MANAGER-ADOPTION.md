## Actual C1 retirement continuation

The isolated shared-source change is limited to `apps/editor/smart-tile/views.js`. Its ordinary manager object retains exactly the original six keys. A module-private WeakMap exposes a separate `createPrivateSmartTileViewsRetirementPort(actualManager)`, which authenticates this exact constructor instance. A record must be a member of its actual retained set and have an actual private retirement state; copied records/foreign managers cannot be tagged in. The immutable owned view and its original methods remain bound to the handle.

`capture(record)` mints a local one-use handle only after actual retirement was attempted and remained unverified. `retry(handle,receipt)` reuses the same dispose/unlink/diagnostics code. It requires the exact positive frozen receipt returned by **that actual view.dispose invocation**, plus actual disposed=true/ownedGeometry=0, and rechecks original record/view membership after callbacks. It removes only that same retained record. A copied/foreign/unknown receipt never releases coordinator quota. Reentry cannot replace/consume an in-flight handle, and no outside record-set mutation is used.

Historical COMPLETE release is distinct from live admission: an exact already-released view may return its same original receipt after context end. That acknowledges only its original released allocations. It cannot credit another view, context/generation, upload or live SourceScope. An unknown/unreleased view stays charged because its actual dispose cannot produce that positive receipt/diagnostics. No live backend-current predicate is imposed merely to re-ack historical release.

Native must acquire this private port **inside its constructor** using its actual underlying C1 manager, then retain/expose the closed continuation through its authenticated source. Calling the lookup on a copied manager or the public forwarding wrapper refuses. Native can retry its own release, pass that exact receipt with the original record handle, and remove its own matching `managedRecords` entry after positive coordinator completion. Its close path must keep context/debt if either domain remains unverified. These are required Artist/Core adaptations, not edits to a350 here.
