# Private same-session Host components

This is a component checkpoint, not a bound C2 Host. `createSameSessionC2Host()` and `createActualSourceReadOwner()` fail closed with `C2_HOST_UNBOUND` / `C2_SOURCE_READ_UNBOUND`. `hostBindingStatus()` reports the missing actual Core, Editor and Artist factories. No new authority, service, planner, meter, durable format or public entry is introduced.

The available pieces are exact v3 operation **data**, an actual temporary authority-invocation guard, a private read frame around the real workbench, and same-ID lifetime bookkeeping. They use the original complete codec, authority and journal. They do not perform a write, accept history, release a native allocation or turn a numerical observation into credit. The enclosing future authenticated Host must pair the actual owner factories and perform their currentness/resource/cleanup checks before calling these internal helpers.

`METHOD-MAP.md` and `method-map.d.ts` give the complete pending integration contract. The requested Kernel semantic adaptation is recorded in `kernel-4ade-begin-control.patch`: `beginPrepare(checkpoint,{action,draft,lockId})`. It passes retained references, uses the already-issued edit ID or one existing history ID, and performs no source inspection. `ROOT-OPT-IN.md` and `root-session-opt-in.patch` record the required separate opt-in at the actual C1 profile constructor; top-level Host fields are ignored. Both are separate from Root's import relocations; the immutable Kernel4ade source is not changed by this candidate.

## Implemented boundaries

- `operation-data.js` requires the actual owned before checkpoint, the actual one-use journal ticket, the captured full Expected, original request ID and retained command digest. It delegates target fields and complete operation binding to the existing v3 domain. Kernel owns actual stage/settle/serialization.
- `invocation-data.js` accepts only a fact which the real authority observation port currently recognizes. It checks actual method, phase, original ID, argument identity and complete before/next WAL JSON. The ordinary checkpoint token omits pending and is insufficient here. It never recursively reads a busy authority.
- `source-read-frame.js` composes the real profile snapshot hook before its output clone, then tags only the exact final return from the same bound `workbench.getSnapshot()`. Copied snapshots and ordinary display reads have no tag. Caught reentry poisons that read; `finally` clears its frame. The enclosing production constructor must authenticate service/session membership and provide actual SourceRegistry/head/context epochs. This component's opaque tag is **not** a Core SourceScope or metering permission.
- `lifetime-data.js` retains the exact original attempt, operation, pending WAL, phase and ticket while outcome is unknown. A confirmed committed outcome cannot be accepted twice; its retry is presentation-only. `settleOwnedCleanup` only records an already-authenticated cleanup result supplied by the future internal Host; it is not a release receipt. It drops its retained references on settlement. Unknown resources must remain charged by their actual owner.

The read-frame test uses the actual existing service factory's private session-membership check, actual private Kernel session, original C1 profile and actual Node Three geometry. Its currentness seam uses actual authority-owned checkpoint and floor-state identities. It proves floor/connection ABA handling at that seam, not unobservable storage ABA or the still-missing Core registry. Invocation tests use the actual authority's WeakMap facts with an explicitly protocol-only observation backend. There is no live work-meter, browser, decoder, native C2 phase or admission proof.

## Pairing still required

Core's static587 proposal is documentation, not an executable owner. Production construction requires its reviewed executable SourceRegistry, same-attempt/continued source validator and actual head/ticket/WAL capacity adapter; Editor's actual nine-hook backend and codec resource-facts adapter; Artist's actual phase/restore/currentness/retirement factory; and one counted bootstrap begun before original source/codec work. One authoring attempt must cover original ingress, history/selected copy, Core, native work, final binding, operation/WAL validation, storage and cleanup. No helper here can replace these ports or supply a fresh budget.

Accuracy favors the existing full v3 document and exact source witness, preserving all 15 native floor records, unknown map properties and injured/spent resources. Efficiency favors one original source/head and one selected history target; no all-history copies or second preparations are introduced. For authoring narrative, one workbench/service and the existing seven verbs keep UI and agent behavior coherent. These are code-based design judgments, not measured live-browser performance or native-memory claims.
