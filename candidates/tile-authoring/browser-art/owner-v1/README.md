## Design choice

For repeated Nautilus painterly previews, provisionally prefer browser logical ownership once its remaining Core/Host ports are paired. Accuracy: it reports actual typed backing capacity and observed API storage/deletion, while explicitly leaving physical browser/driver/GC quantities unmeasured. The strict profile remains useful compatibility evidence with different physical-release semantics and is unchanged.

Efficiency: real tiny component measurements show steady decoded/derived/active-row stocks after repeated edits and range reuse. This is resource/lifecycle evidence, not a frame-time or large-map benchmark. Full original pages are decoded once per palette lifetime; per-view marks add no geometry. Processor cost at production map scale is unmeasured.

Narrative: the reviewed native screenshot shows the original painterly blood stamp over the existing concrete finish; a repeating road detail uses the same source-grid material path. Painted detail preserves the intended visual language without sculpting every mark. Preference for this approach in Nautilus map authoring is a subjective visual judgment. Tinderbox fire and tactical game adoption remain explicit consumer decisions; no donor or pin changes.
