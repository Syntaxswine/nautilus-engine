# Distributable packages and shared assets

The source checkout is the complete authoring/review repository. The default compatibility package has an explicit file whitelist: public module dependency closures, required runtime paint/catalogue resources, schemas, notices and concise contract documentation. It excludes editor applications, test fixtures, source plates, review screenshots, detailed source artifacts and prebuilt model binaries. Original vendor bytes stay unchanged in the repository.

node tools/distribution.mjs --write deliberately refreshes the root package whitelist after a reviewed public dependency change. npm run check verifies the list; it does not rewrite it. npm pack --ignore-scripts --dry-run --json shows the ordinary package inventory. The versioned package export map prevents supported consumers from depending on donor/editor paths.

Optional offline distribution profiles are built in artifacts/distribution with npm run pack:core, pack:renderer and pack:assets. Each package carries a hash/byte-count provenance inventory. Core contains only headless public API dependencies. Renderer provides explicit host-supplied Three adapters, the optional contour effect and the shared Three entry. Building-assets contains the opt-in original glTF/blueprint/map payload and painted atlas; games that create models procedurally need only the renderer profile's runtime resources. The standalone editor is the separate npm run build output, never a mandatory game runtime dependency.

npm run test:package packs the core, installs it offline in an isolated temporary consumer, imports only its public exports, and checks editing/history, schema URLs, save reload, manifest discovery and the Tinderbox adapter. It copies the byte-verified, test-only game compiler/simulation into that independent consumer, then exercises real wall collision and deterministic replay after reload. Those game fixtures are never shipped in the package. The temporary install is removed afterward. This catches omitted package dependencies that source-tree tests can hide. Consumer conformance tests additionally run pinned real Tinderbox modules; fixtures are excluded from the shipped package.

The optional headless `./rules/progression` export and progression structural schema are included in the core dependency closure. The offline installed-package proof exercises level rewards, point allocation, practice, resource preservation and duplicate delivery after save/reload. The reference UI and its sample-outcome harness remain in the standalone build, outside the headless runtime package.

## Borrowing assets

All three games can import listSharedAssets/sharedAsset from ./assets for stable namespaced asset IDs and explicit availability notes. The catalogue is headless and generated from reviewed registries. Content-binding-required entries need a deliberate consumer model/material/content binding; inspection-only entries preserve format limitations. Discovery is not a promise that every game can place every content type.

./items provides headless rock actions and sidecars; ./items/three exposes createRockModel(THREE,{radius,seed,color}). It owns only its geometry/material and removes its own root on dispose. The original item:rock discovery record points to that factory. Hosts bind pickup, inventory, collision, sound and guard behavior explicitly. The installed core proof also exercises pickup → throw → impact → hearing and midflight save/reload.

./assets/three exposes loadBuildingAssets(THREE,{renderer,providers}), with original and gross providers. It returns create(id) and dispose(); created instances expose root, setView and dispose. It never creates or disposes the host renderer. The library owns loaded textures and its instances, and dispose closes both. Instances of one original design share a single built template: each root is a clone with its own nodes and view, sharing geometry and materials (treat those as read-only), and the last instance of a design releases the template. Gross houses remain one model per instance, because their cutaways clip through per-house wall materials. Pass providers:['original'] to load just the original catalogue. ./buildings and ./buildings/three expose recipes/compilation and direct procedural models; ./roofs and ./roofs/three expose roof data and meshes. Hosts retain their own Three instance and metre scale.

These visual assets carry source identities separately from map capability promises. Borrowing a roof mesh does not select fire, collision, navigation, character scaling or game save policy. See docs/adapters/tinderbox.md for the first deliberately bounded map adapter and its real-game conformance proof. Each game adopts a pin as its own reviewed change.

The optional @nautilus-engine/building-assets package exposes listBuildingAssets and buildingAssetURLs from its root. Pass a discovered namespaced building ID; the result contains model, buffer, blueprint and atlas URLs relative to that installed package. Only the 48 original exported buildings belong to this payload; Gross assemblies use the renderer provider. npm run test:assets installs the real tarball and resolves all of these resources. Source notices and complete original third-party licenses accompany the applicable runtime distributions.

## Optional composition, worlds and floor views

The headless core also exports `./runtime`, `./world`, `./floors` and `./adapters/farmyard/rules`. Their static dependency closure contains no editor, DOM view, Three or internal scheduling. The compatibility package additionally exports `./floors/ui` and `./floors/style.css`; include that stylesheet explicitly. The headless profile excludes both browser subpaths and their files. No new mandatory renderer package is introduced for navigation data.

Installed-package checks compare all six actual Farmyard quickplay profiles and fourteen weapon blends against byte-preserved pinned source copied only into the isolated test consumer. They also compose a stat module over retained host actors, verify teardown ownership, serialize/query an upper floor, navigate real floor IDs and reject the browser-view subpath from the headless package. Test source, proposed actor/height binding inventories and browser examples stay outside runtime tarballs.

Build-time dependency enumeration parses actual module references rather than matching the word 'from' inside ordinary data strings. No application module executes to discover its distribution closure. Source inventories and byte hashes remain explicit.
