The [usage card, installed example and builder checklist](../../../packages/tile-visuals/README.md) describe the bounded provider. `examples/canonical-tile-art.html` reviews joined paving, native binary fields, a courtyard hole, clipping and a curved constant-width path. The old workbench stays available separately. Root alone owns public registration and integration; this provider is packaged privately for proof.

## Boundary and renderer evidence

The actual registered core reopens/validates the complete bundle and supplies inspected geometry. Detached records retain raw controls, source IDs, native floor heights, layer/channel/profile/material/UV data, canonical sample arrays and readiness. Surface triangles reference every external sample; separate per-port geometry retains every canonical parameter tangent. No copied catalogue handle, lab matcher or lab save format is used.

The temporary policy `canonical-surface-v1-cuts16-interior8-16-32` follows Architect's relayed v1 decision: core internal cuts at 16, field interior grids at 8/16/32, external schedules unchanged. Region/path interior refinement leaves contours fixed. Quantization-limited refinement retains the original valid planar face and reports that event; no boundary is independently refined off its agreed chord.

Combined tests cover all 18 binary mask/saddle variants across eight D4 placements; mixed-detail actual border attributes/colours; canonical schedules of 7, 12, 17 and 40 segments; curved/partial interfaces; native 2.12 m floor height applied once; holes/clips; raw precise cubic controls; culling/owner deletion; unsupported-profile preservation and partial-failure/idempotent disposal. The scalar mesh's checkerboard corner connectivity is tested independently of core's topology metadata. That is a paint/model proof, not walkability.

Fresh contour evidence is in `measurements.json`. For the five measured binary cases, maximum dimensionless scalar residuals at mesh zero contours were approximately **0.01902 / 0.00753 / 0.00290** for 8/16/32 interiors. These are model residuals, not metre errors. The 64-segment radius-3/radius-1.4 courtyard boundaries measured maximum radial segment deviations of **3.614 mm / 1.687 mm**. These apply only to the measured new meshes; no general physical accuracy or device-performance claim follows.

## Remaining integration work

Public provider exports/resource closure/guide registration belong to Root. Smart Tile authoring, atomic repair/history/locks and game adoption are separate. Variable-width ribbons, Boolean source graphs, arbitrary sections, graded stairs and full-edge-zero field exposure remain staged until actual extensions exist. This provider supplies no solid extrusion, skirts or game query/support/navigation/fire/water behavior.

Run `node tools/check-tile-visuals-source.mjs`, `node --test tests/tile-visuals.test.mjs`, `node tools/measure-tile-visuals.mjs`, `node tools/test-tile-visuals-package.mjs`, `node tools/verify-tile-visuals.mjs` and both modes of `node tools/review-tile-visuals.mjs`. Logs live under ignored `artifacts/tile-visuals*`; the committed acceptance summary and preview hashes record the final run. Every review owns a bounded isolated browser/server and closes them in `finally`.
