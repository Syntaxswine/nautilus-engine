# Native-scale angled walls

**Context.** Gross catalogue building plans for Tinderbox require angled rooms and bay windows. All games share the original asset dimensions. The inherited AFT editor represents only east/south grid edges. Alternatives are stair-stepped grid boundaries, stretched one metre wall meshes, or explicit measured runs assembled from native panels and cut ends.

**Accuracy.** Recommend measured runs. They retain straight diagonal faces, their true lengths, two metre story height, 0.16 metre thickness and 2.12 metre floor spacing. A diagonal grid step is √2 metres; stretching an existing one metre asset would break the user's scale requirement. Local-frame intersection tests follow the rotated wall, including story gaps. This is geometric accuracy, not validation of building structure, fire behavior or a historical floor plan. Rectangular floor tiles and the existing roof system retain their inherited conventions.

**Efficiency.** Code inspection: previews validate a candidate without rebuilding a second game engine; geometry rebuilds on edits/view changes; full panels share instanced meshes and geometry. Cut widths add geometry variants. Wall collision currently scans the runs; the wall-aware validation pass can cost more than grid-only reachability. These are implementation estimates, not device/frame-rate measurements. A spatial index is a later improvement if representative dense maps show it is needed. Explicit run/panel limits bound authored data; the existing bounded seeded block search is reused.

**Narrative.** Subjective preference: straight angled facades and exact bay-window corners suit Tinderbox's period architecture better than a stepped approximation. Measurements, endpoint joining and a plan camera help artists trace plans and carry a reusable kit into later games. Existing square walls remain convenient for grid-aligned tactical layouts.

**Recommendation and status.** Implement native-panel runs as an optional shared format feature and editor mode. Preserve square edge walls, donor bytes and existing formats; require an explicit consumer capability. This work implements shared authoring, rendering, geometry helpers and map/block preservation. It does not migrate consumers or claim a fire/collision integration for each game. Generator seam continuation for angled runs is deferred and rejected explicitly, while inset angled blocks are supported. Prefer this foundation for Tinderbox catalogue tracing and future angled buildings; keep the original edge tool for square layouts.

**Evidence.** `tests/wall-runs.test.mjs` checks native geometry, history, import validation, exact block transforms, oriented collision, reachability, capability rejection and seeded generation. The generator's feature-free output is compared directly with its immutable AFT source. Browser review verifies the actual shared Walls controls and native-scale bay example. Required source hashes and upstream regressions remain part of delivery.
