Production behavior
The native factory owns its original image placeholder immediately. Abort settles without waiting for TextureLoader's unabortable callback. Late success has no publication rights. Resource fetches remain concurrent within one native candidate. The retained-yard owner registers generations before invoking observers and waits for predecessor settlement/cleanup before conflicting acquisition. The accepted scene remains installed and frozen until the complete candidate commits. Failed or cancelled candidates retain the exact accepted checkpoint. Successful host restore deliberately invalidates train control/lease revisions; no save is rewritten to claim whole-host equality.

A private once-only ownership journal drains every registered resource and every synchronous disposal listener, including Three renderer listeners, before reporting AggregateError. It preserves original failures alongside cleanup errors. Per-instance event dispatch wrapping uses the pinned Three r180 EventDispatcher contract; it is not a global runtime patch or public service. Parent target/depth cleanup completes before nested errors escape. Body/crawl cleanup includes detached original weapons and late skeleton textures; motion/pose math and supported profiles are unchanged.

The private paint adaptation is reproducible from the exact existing AFT Git object. Original vendor bytes remain unchanged. Projection shader expressions, program keys, full image resolution and 2048×1024 projection dimensions are preserved. A synchronous state guard captures/restores target face/mip, default logical and currently bound physical viewport/scissor/test, output space/tone mapping and clear colour/alpha. Borrowed targets are never owned, mutated or disposed. Unsupported finite/FBO/XR/colour configurations refuse before projection. The guard attempts every restoration even if one setter throws; it cannot promise physical recovery from a renderer implementation whose own restoration API refuses the saved state, and reports those failures.

Design evaluation (docs/design-evaluation.md)
Accuracy: private transactional cleanup/state restoration is preferable to the original unguarded sequential cleanup because failures leave neither a partially retired actor nor corrupted borrowed renderer state. This is demonstrated lifecycle correctness, not a physics/visual realism improvement. Shader parity and unchanged motion equations preserve the accepted visual/profile behavior; earlier accepted native pose captures remain the pose evidence.
Efficiency: the repair adds bounded per-actor journals, listener snapshots at terminal disposal, state reads and latest-generation retirement ordering. These are code-based costs; no CPU/GPU timing, FPS gain or memory-saving claim is made. Serializing conflicting generations can delay replacement until cleanup ends, while safe candidate-local resource/actor preparation remains independent. The unsupported-state refusal avoids silently normalizing a host's renderer.
Narrative: retaining the complete accepted yard during preparation and refusing partial publication is preferable for the ordinary retained-town/native-asset use case because operators, equipment, settings and resources stay coherent. Whole-host restore keeps its intentional control lease invalidation rather than forging equality. Existing explicit native profiles and full-resolution paints are retained for game compatibility.

Recommendation: integrate this bounded lifecycle repair after Architect review. Source sharing remains a separate measured proposal; finite heat/publication, native disc, overmap, Artist/UI/Editor and consumer pins remain outside this assignment.
