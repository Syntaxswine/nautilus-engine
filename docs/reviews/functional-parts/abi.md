Native axes, shapes, field names, transforms, provider markers, units and ownership are specified in the guide and executable schemas. Runtime code contains no branch keyed to a building name. A second transformed instance and third wider layout compile and run through the same path. Body fit is measured against the selected conservative maximum; the conformance aperture is deliberately 1.85 m for its 1.7 m test body. It does not approve the original 1.65 m kit opening for that body.

Source-map IDs connect collision pieces, moving leaves, portals, stairs and render records back to stable authored instance/part IDs, definition ID/version and property paths. Generated IDs are reversible and bounded without truncation. Dynamic leaves are absent from static collision. Slab/wall holes are real missing geometry, while declared landing surfaces retain full-footprint support. Expanding a small repeated recipe stops at the output budget before allocating an unbounded result.

## Evidence and limits

- Full source integrity/headless dependency checks passed. A full-suite regression caught an accidental world-core -> parts-core dependency; the refusal guard now lives inside world-core and its existing self-contained-import check passes unchanged.
- Final entry inventory caught an indirect legacy/donor dependency through capability negotiation. The existing negotiation implementation now lives in an independent shared module; legacy public exports and `CompatibilityError` identity remain the same. An enforced static closure check keeps parts/fixtures inside engine-owned packages, with no donor/editor graph. Machine evidence records the resulting entry source bytes/files.
- All 404 engine tests and 32 upstream tests passed. Focused compiler/runtime/boundary tests include strict raw data, native transforms, source/property diagnostics, body/route clearance, static/other-leaf and live/offscreen blockers, stale/repeated actions, relocking policy, complete journal tamper/stale-geometry rejection, host-resource preservation and durable effect claims.
- Offline installed core proof passed using only public exports/resources. It runs the exact guide example, checks all three layouts, enters a door, climbs both directions and restores a mid-action save. Optional compatibility title/stylesheet/guide package proof also passed.
- Independent `jsonschema==4.23.0` validation passed four draft-2020-12 schemas and 21 positive/negative samples, with all references resolved locally. Python dependencies are test-only ignored artifacts, absent from engine packages.
- Static build passed. Nine browser checks passed on the existing title/reference yard, including desktop, touch, 320 px phone and 640 px reflow, door/key/occupancy feedback, continuous stairs, mid-save import/reload, failure/retry, cancellation and disposal. No console/resource errors occurred. This browser fixture is the existing SVG reference, not a rendered native parts/art acceptance.
- The disposable review server/browser closed through their owning APIs. Independent PID + creation-time and listener verification found neither exact original helper and zero listeners on its port. No task-owned preview/service is retained.

`abi-measurements.json` records Node/runtime/device, method, input/output counts/bytes and local compile/commit/restore timings. Compiler workloads use one, two and three assemblies; runtime uses one actor, 23 static surfaces and 240–280 receipts. The headless core tarball sizes and integrity are recorded separately from the optional compatibility package. Timings are observations on an uncontrolled desktop, not speed claims, budgets, frame rates or physical-device evidence. No renderer, GPU workload or real art was measured.

The runtime deliberately stops at 4,096 combined action/claim receipts and an 8 MB complete checkpoint. It does not evict deduplication records or promise indefinite frame-sampled play. A production high-frequency session needs a reviewed checkpoint/receipt compaction design. Door clearance reserves conservative AABB motion envelopes; it can refuse a physically possible arc. This profile excludes mesh/curved-world physics, arbitrary rotation/scale, paired leaves, fire/collapse and inferred catalogue circulation.

Event claims require host persistence before presentation dispatch. Exactly-once delivery to an external sink still needs the game's idempotence/transaction. Permissions, keys, AP/costs, inventory, damage, clocks/RNG and narrative effects remain host-owned. Save hashes express consistency/content identity, not security signatures. The existing portable map/block, character and strict world-v1 formats retain their separate schemas; legacy readers and Tinderbox flat-yard explicitly refuse new parts envelopes.

## Integration handoff

Architect can distribute this fixed commit's schemas, exports and JSON fixtures to Artist, Editor and UI. Artist supplies the measured real native kit/actor and asset-to-semantic parity; Editor owns placement/transform/copy/delete transactions and history, remaps fresh IDs/internal edges and declares the external-copy policy; UI supplies the reviewed generic presentation/player and readiness/title bootstrap using the host's authoritative core provider. A second physical installation of core cannot adopt another copy's private scene/runtime handle.

Real editor -> validate -> play -> door -> both stair directions -> obstruction -> mid-save/reload, native paint/rig/animation, desktop/phone interaction and presentation ownership remain integration acceptance. The checked conformance data does not satisfy those visual/product items. Existing bear, Coldwell, title and grenade work stays on its own fixed reviewed branches/contracts. No donor/game pin, main merge, production release, deployment or Sites audience is changed here.

For the bounded two-story authoring use case, explicit native semantic recipes are the provisional preference: code-backed tests make openings, poses and support agree (**accuracy**); finite AABB work and measured small workloads provide a bounded starting point, with broader performance unmeasured (**efficiency**); native art and game-owned policies preserve each game's intended experience (**narrative**, judgment). More detailed geometry/fire remains appropriate where the game's central mechanics justify it. Retain the separate world/interaction profiles for compatibility and revisit the choice with actual kit, integrated gameplay and device evidence.
