# Floor-wheel browser review timing

Reviewed baseline: main `5a5fb93c91f45948f075bc981e34397983babd02`. The [post-merge run](https://github.com/Syntaxswine/nautilus-engine/actions/runs/40919483681) failed after five separately awaited native wheel calls: the harness expected floor 11 and observed floor 12. Browser errors and resource failures were empty. That run did not capture wheel timestamps, so its exact event gap cannot be recovered from the failure log.

The harness assumed those calls formed one gesture. The controller instead defines a fresh gesture after an **adjacent delivered-event gap of at least 180 ms**. Automation RPCs and the intervening state wait impose no upper bound on that gap. Independent trusted native events, including the new review's observed idle-separated pair, follow this rule: floor 10 → 11, then floor 11 → 12 after the recorded idle gap. This supports a harness timing defect; attributing the historical CI failure to one particular gap remains an inference. No runtime component, threshold or public API changes.

The revised check keeps native input for floor selection and scope. It waits for the same-element post-handler observer to record each delivered event, verifies exactly two trusted selector events and one trusted scene event, and records timestamps, deltas, trust, cancellation, resulting floor, zoom and page scroll. The first selector event changes to floor 11; a later native event changes to floor 12 only after an observed gap ≥180 ms. Both leave scene zoom and page scroll unchanged. Native scene wheel input still changes zoom to 105 while leaving the floor at 12. An ancestor observer confirms selector events stop propagating and scene events reach it.

Continuous gesture and inertia acceptance use a fresh controller/DOM fixture in one browser task, with explicit synthetic `WheelEvent.timeStamp` values. Its gate never receives native timestamps; the original reference widget never receives synthetic timestamps. The fixture is disposed before later native input. This preserves the controller's monotonic-time contract and makes the burst independent of RPC/runner load.

The deterministic sequence delivers 121 events across 600 ms with 5 ms adjacent gaps and requires exactly one floor change. A 179 ms gap must remain latched; a 180 ms gap must permit the next step. A decaying inertia tail must stay latched, and another 180 ms gap permits an opposite-direction step. All 128 delivered events must be canceled and the exact floor-change sequence is asserted. Two additional Node tests cover the long burst/boundary and a sparse delivery sequence spanning multiple gestures.

`artifacts/floor-navigation/wheel-events.json` is written in finally, including when an assertion fails. It distinguishes trusted native events from the controlled synthetic fixture and is referenced by hash from successful acceptance metadata. The existing CI artifact upload can therefore retain timing/state evidence for future failures. No retry, widened idle threshold or omitted floor/zoom/scroll assertion is used to hide timing.

Run `node --test tests/floor-navigation.test.mjs`, the required source/test/upstream/build gates, and `npm run review:floors`. Frozen acceptance, event traces, gate results and verified helper cleanup are recorded in [the evidence directory](evidence/floor-wheel-timing/). No preview service is retained. Root owns integration and release tagging.
