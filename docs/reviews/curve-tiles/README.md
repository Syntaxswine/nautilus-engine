# Reusable tile art handoff

This candidate supplies a procedural art workshop for the user's request for broad tile variations with reusable alignment rules. It covers 294 compact recipes plus continuously adjustable parameters, independent family modules and a host-Three preview. No consumer pins, donor bytes, public exports, global schemas/whitelists or editor storage formats change in this branch.

Start with the [usage card and acceptance checklist](../../../packages/curve-tiles/README.md), [recipe inventory](../../../art/curve-tiles/catalogue.json), [source ledger](../../../art/curve-tiles/source.json), [contract coordination](contract-proposal.json) and [registration request](registration-request.json). `examples/curve-tile-art.html` works in source and in the static build. Run `node tools/review-curve-tile-art.mjs --source` or omit `--source` for the build; each review owns a bounded browser/server lifetime and closes both in `finally`.

## What is ready

The art generator demonstrates actual border position/normal/UV continuity across mixed interior detail; bounded painterly vertex tint leaves borders unchanged. The shoreline reference preserves the reviewed AFT field's 16 masks and three variants. Boolean fields cover holes, caps, T/X junctions, inner/outer arcs, shallow/45-degree cuts, uniform/variable-width strokes and cubic S bends. Ramps/stairs preserve native 2.12 m endpoints; supplied path sections produce curved panel fences and cornice trim. Layered water/bank/bridge/kerb visuals are independent of the old one-feature-per-block-side profile.

Focused tests measure 3,456 ordered AFT border comparisons, 256 corner-mask/saddle combinations and 576 neighbor interfaces across four authored rotations and their mirrors. They inspect actual mesh attributes, triangle winding, whole-cell complementary surface coverage, off-midpoint crossings, seed isolation and disposal. The rotation tests author transformed inputs independently; they do not stand in for the Coder's canonical transform conformance.

## Integration status

The Architect's frozen contract spine and provisional Coder API names are recorded in the adjacent coordination file. A fixed reviewed kernel commit and exact checked projection shapes were not supplied when this artist checkpoint was prepared. Therefore this branch does not import worker files, claim `./tiles` availability, publish another engine save format, or bind the lab edge comparator as authoritative matching. The offline installation proves artist/renderer ownership with actual declared core/renderer packages; it cannot prove the missing canonical tile projection adapter or combined Smart Tile workflow.

The remaining artist step after receiving that dependency is to consume its detached validated projection, map exact canonical ports/border profiles into these meshes, and run combined core/provider conformance. Root owns registration and integration; Coder owns catalogue/layout/bundle validation and repair; Editor/UI owns Paint/Rectangle/Path, atomic neighbor updates and locks. The lab records are not save data for that workflow.

## Design evaluation

| Alternative | Accuracy | Efficiency | Narrative and recommendation |
| --- | --- | --- | --- |
| Fixed AFT per-tile shoreline masks versus parameterized regions/paths | The AFT field guarantees a known corner/border behavior and decorative variation. Parameterized geometry expresses real plan radii, widths, skew cuts and compound paths; grid triangulation is still an approximation, with no surveyed physical calibration. | Code inspection: a small descriptor avoids a Cartesian mesh archive; generating mixed cells costs CPU and geometry. Browser triangle/draw counts are recorded, not a frame-rate or device benchmark. | Prefer parameterized semantic regions/paths for Nautilus authoring and Tinderbox architecture; retain the original AFT mask profile for compatibility. Farmyard can select lower interior detail while keeping the same border. Subjective visual preference: painterly materials carry small detail, geometry carries silhouette. |
| AFT whole-block connection policy versus layered ports | Whole-block road-centre rules are predictable but do not describe concurrent water, bridge, kerb and fence interfaces. Typed layer/channel profiles describe those separate structures more faithfully. | More interface records and validation work are expected; no gameplay CPU benchmark exists. Lazy family imports avoid charging every game for all art. | Prefer the new shared layered contract for reusable tools; retain old block restrictions only in the named legacy profile. No legacy data migration is performed here. |
| Independent tile skirts versus welded shared borders | The reviewed cliff design's weld-before-skirt principle prevents internal walls. The study preserves canonical border geometry across LOD, but exact full-edge zero contours and closure still need the kernel's ownership decision. | Measured tests compare mesh attributes; no watertight/closed-manifold or support claim is made. Current study meshes prioritize reviewability over final triangle optimization. | Prefer canonical matching and exposed-interface skirts for all three games. Geometry ownership must survive culling/deletion; instance IDs cannot suppress real borders. |
| Painterly skins versus modeled surface relief | Existing painted stone/wood/plaster express color and small detail, not physical roughness or collision. Native profiles retain visible stair/kerb/cornice silhouettes. | Code estimate: texture reuse costs less geometry than modeled masonry; no comparative GPU timing measured. The same atlas supplies all review scenes without new bitmap duplication. | Prefer painterly skins for general buildings/paths in all three games, with physical profiles where tactical readability or architectural silhouette needs them. Gameplay and Tinderbox material/fire properties remain explicit consumer bindings. |

## Reproduction and evidence

Run `node tools/build-curve-tile-art.mjs --check`, `node --test tests/curve-tile-art.test.mjs`, `node tools/test-curve-tile-art-package.mjs`, the four project gates and both browser review modes. Machine logs and temporary helpers live under ignored `artifacts/`; the committed acceptance summary records final results. Review images live under `previews/`.

Known limits: appearance only; open surfaces rather than closed solids; no final kernel projection adapter; no editor repair/save/undo implementation; no game adoption. Direct border material/profile differences must be explicit transition recipes. Sampling density and quantization are separate policies, not accuracy claims. No literal finite catalogue can enumerate every possible curve; the tool generates bounded variants as requested.
