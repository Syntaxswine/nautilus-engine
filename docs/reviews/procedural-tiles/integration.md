## Registered contract

The optional `./tiles` entry is declared in the compatibility and core package
profiles. Four independent v1 schemas are registered with stable URNs and actual
package-relative URLs: recipe, layout, complete authored bundle and derived
compiled inspection. `nautilus-procedural-tile-boundaries-v1` advertises the
available engine boundary/preparation code. It does not advertise any of the six
borrowed presentation/query/support/navigation/fire/consumer services.

Raw line, arc, cubic and compound controls, anchors, template pins, metre heights,
channels/layers, locks, seeds and bounded authoring extensions remain save data.
One semantic shape may cover many derived cells. The same pure resolver prepares
edits and repair; consumers own the complete atomic commit and one history entry.
Unresolved authoring, resolved boundaries and live adoption remain separate.

Root integration adds discovery documentation, schema/capability registration,
an explicit distribution whitelist, the standard integrity check and the actual
`npm run test:tiles` CI gate. Historical absent-export/pending-registration tests
now demand the real installed package. The runtime usage card reflects reviewed
availability while retaining unbound provider states. A separate scoped review
verified actual registration, document identities, package contents and readiness.

The new default installed test exposed inherited `NODE_TEST_CONTEXT` suppressing
the nested independent runner. The package tool clears that context and refuses
missing/nonpositive summaries, any failed/cancelled/skipped/TODO tests, or a pass
count different from the total. The installed correction suite must really run.

## Remaining broad tool work

The artist's separate `7d7b1ccee54b1eba05b2f60563d4ab5ab4d002ab` checkpoint
contains 294 visual studies, not 294 adopted canonical recipes. Representative
sheet, cubic S-bend, layered bridge/water and native-height previews were reviewed.
Its lab matcher/save document is not a second public authority.

The coverage mapping identifies exact field/line/arc/constant-width path intent,
measured contour approximations, and explicit missing extensions: editable Boolean
union graphs, varying width, native cross-sections, stairs/graded cell providers
and full-edge zero exposure. Legacy AFT variation keeps its separate evaluator.
Core/art border schedules also need one agreed adapter policy; neither side may
silently resample away canonical external constraints.

Prefer parameterized semantic regions/paths and common boundary rules for the
expansive Nautilus tool, retaining the old block profile for compatibility.
Accuracy: native controls express more shapes while approximation bounds remain
explicit; neither art meshes nor metadata prove support or traversal. Efficiency:
compact recipes avoid a Cartesian archive, with bounded generation/repair cost;
device performance remains unmeasured. Narrative: optional painterly terrain,
roads, water, barriers and native-height families suit all three games while
letting each game choose its presentation and simulation detail. This is a
provisional design recommendation until combined provider/device evidence exists.

Next integration remains the canonical artist provider and missing shape/profile
work, followed by Editor/UI's single Paint/Rectangle/Path flow, automatic joins,
locks and atomic history. Query/support/navigation/fire and real-game adoption
need their own actual providers. No consumer pins or Sites audience settings
change as part of this foundation.
