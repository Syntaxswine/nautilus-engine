# Interface decisions requested from Architect

The concrete proposal is contract.schema.json/api.d.ts plus contract.md, not an implemented runtime. Recommend freezing these decisions before Coder/Editor/Artist/UI implement the shared service.

1. **Outer document policy:** approve the strict authoring-module@1 plus complete-source projection, with Editor choosing a fresh outer checkpoint version/namespace (provisionally v3) and reusing its ONE policy/journal/authority. Existing v1/v2 files remain on their supported workshop. Which exact Editor floorBinding/finishBinding shape should the projection preserve verbatim instead of its proposed floorProfile/catalogue binding? The current proposal separately binds projected workspace digest, actual full host-document digest and durable host-authority token. It has exact native floors and ID/version/content digest, never a profile ID alone.
2. **Surface and compositing profile:** provisionally prefer owner-local level-top frames, authored-grid RLE masks, stamp/detail TRS and linear premultiplied source-over from declared straight-alpha sRGB PNG/WebP. Artist must bind real clipping (including holes), D4/group phase conversion and resource accounting. Approve as the initial contract, or restrict the first implemented region profile further until actual topology/clip proof? Holed source is explicitly unbound, not implicitly supported.
3. **Review/agent transport and budgets:** approve one live JSONL host connection with describe/snapshot/query/prepare/apply/cancel/recover; portable command JSON never transports the retained commit lease. Proposed counters preserve the blueprint8/4096/1024/32MiB and existing root/triangle/cell totals, plus the finite packet/library/image/mask limits in discovery. Please freeze/refine those unmeasured policy ceilings and the no-change refusal before implementation; resource/decoder attestation and the actual aggregate ledger remain mandatory.

Preferred foundation under the three criteria:

- Accuracy: exact version/hash pins, original analytic controls, stable owner/surface/floor anchors and explicit graphic/physical separation preserve authoring meaning. A simple existing v1 grammar plus required clip proof is preferable here to an unrestricted mesh/JS tile format. Physical calibration/support/gameplay remain unimplemented.
- Efficiency: sparse records, shared immutable resources and one authority are preferable to a bitmap/material per cell or a second overlay journal. Pair/contact/clip/decoder costs and all proposed ceilings remain unmeasured; the ledger arithmetic is a source-based estimate. Let actual desktop/phone evidence choose shader compositing versus clipped geometry/batching, rather than embedding a renderer choice in the data schema.
- Narrative: local wear/road/vegetation graphics can distinguish reused tiles, while reusable presets and identical human/agent commands support shared building tools. This is a subjective authoring preference; each game's art/blood/fire/vegetation/time policies stay outside the contract.

Compatibility choice: preserve the closed public v1 recipe/bundle API, old source/versions and named profiles; put new functional state in a typed new module. Deferred world-fixed/path anchors, animated marks, extra material channels, physical craters/plants and other surface frames require separately reviewed capabilities. No donor/pin/public export/registry or audience change is requested in this checkpoint.
