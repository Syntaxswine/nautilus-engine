# Tile authoring core contract proposal

C0 realignment starts from fixed Core `7772910059d86c00c84475af489be812ff225c5d`. Scope: Architect blueprint `b850e20e2fdd85435d33f16327482b80380af728`. Separate branch/checkpoint; accepted stack planner `45ecaef16bb39424c8b885d53acb4371654b4fa0` is preserved. This delivery contains private schemas, types, discovery, examples and contract proof tools. There is no command reducer, authoring service, CLI entry, overlay renderer, journal implementation, public registration or deployed workflow. Normative proposed structures are `candidates/tile-authoring/core/contract.schema.json`; types are `api.d.ts`.

## One source and one authority

Propose a strict `nautilus-tile-authoring-module@1` alongside the unchanged v1 tile bundle. It contains immutable library definitions/presets/artwork, owner pins and a typed decoration sidecar. No functional overlay is stored in recipe interior or layout extensions. Existing source extensions remain ordinary preserved source without new functional interpretation.

The saved authority is exactly `nautilus-tile-workbench-document@3`: `kind,version,id,sourceJSON,floorBinding,finishBinding,tileBundle,constraints,contentRevision,authoring,resourceRefs`. The six B1 fields are retained in full: `id,sourceJSON,floorBinding,finishBinding,tileBundle,constraints`. `floorBinding` retains its kind/version/table ID, profile ID/version, original source SHA and all fifteen labelled native floor records with legacy-layer/authored-tile provenance. `finishBinding` retains `{id,version,digest}`. The fixed B1 policy input is `4b0499cc776fcd85fdd415fa7344982b75fbf8fb`. Constraints stay typed and non-null in v3. The authoring module is the sole home for library/decorations/ownerPins; resourceRefs contains references, never another artwork library.

`nautilus-tile-authoring-source@1` remains the frozen read-only command/query planning view. Derive it from a validated complete document; never save it, parse it as a v3 alias, or turn its reduced floorProfile/finishCatalogue into saved authority. Its revision views contentRevision. Snapshot returns both the full document and that consistent view. Review returns the full `targetDocument`, not a partial source target. `hostDocumentDigest` covers the entire v3 document; workspaceDigest covers the derived view. Expected's historical floorProfileDigest name now binds the **full** floorBinding; resourceSetDigest binds the durable typed resourceRefs set. Host authority/context tokens remain independent of both content hashes.

Each ordinary nonempty accepted command increments contentRevision exactly once; overflow refuses. Exact whole-document Undo/Redo restores the complete historical document, including its older contentRevision, original JSON and resources. Freshness comes from the complete checkpoint/journal token and context, never a monotonic contentRevision assumption or revision alone. No-change batches return `NO_CHANGE`, make no write/history entry and preserve redo. Metadata/library/decoration-only commands preserve the exact tileBundle/layout revision and constraints, require no geometry prepare and report `source-unchanged`; active geometry changes use one actual public-v1 preparation. The same Editor-owned codec, journal, retained review and history serve UI and JSONL.

## Immutable content

A definition, preset or artwork record has `{kind,version:1,id,revision,body,contentDigest}`. `contentDigest` is SHA-256 of the canonical JSON record WITHOUT contentDigest, using the public tileLayoutToken canonical-data profile. Pins always name `{id,revision,contentDigest}`. Version is the data grammar; revision identifies immutable content. Create starts a new identity at revision1; revise appends the next revision against an exact base pin; clone creates a fresh identity/revision1 while preserving original geometry/control/anchor data except explicitly new recipe identity. Library IDs occupy one global identity namespace across kinds; pins resolve the expected record kind as well as identity/revision/hash. No implicit latest version. Same identity/revision with different content refuses; exact duplicate records may coalesce in a meaningful import batch.

Definition body embeds the complete CLOSED actual public-v1 recipe, original controls, named surface descriptors, required profiles and source/license notices. Unused/referenced old versions remain. Different v1 recipe bytes cannot share a recipe ID across retained definitions; a changed version needs a distinct bounded recipe ID so old and new can coexist in the ordinary v1 catalogue. Caller supplies explicit IDs; bounded digest-derived names are recommended, without truncating arbitrary user names. Active/retained map recipes still obey the existing reference32 cap; unused old map recipes are not pruned to evade it. Library capacity is a separate proposed bound.

Initial source profiles: local level region, local flat field and local isolated level path using actual v1 source. World frames, new clipping, grades, solids and unproved intersections refuse. The compiler derives required capabilities, dependencies and costs from actual source; caller requires lists, family labels and declared costs cannot waive them. Recipe validity is necessary but insufficient: the eventual profile validator must prove level controls/height amplitude, floor offsets, topology, isolation and the real provider's support within finite work. Holed-region example data loads in public v1 but explicitly requires `source-region-holes-clip-v1`; this proposal does not supply or certify that clipping provider. Original unrecognized/unsupported packs may be retained read-only outside adoption; strict import never drops unsupported records and calls that success.

A preset pins one exact definition plus explicit default layers/marks. `preset.place` chooses `copy-explicit` or `empty`, with explicit fresh owner/mark/layer IDs and complete remap tables. Two placed copies are independent. Saving/revising a preset never updates prior placements. `placement.upgrade` explicitly selects owners, exact from/to pins and original recipe-anchor subsets; locks, public repair and every affected decoration decision must pass before one atomic acceptance.

## Surface, grid and graphic source

Native coordinates are metres `[x,y,h]`; rotations are radians. Rendering uses the existing borrowed provider's axis conversion. A semantic surface has a stable ID, original source anchor ID, floor slot/offset, local level frame, authored grid and exact geometry/frame digests. The initial surface frame uses local XY axes and up `[0,0,1]`. Placement/D4 is applied once by the owner. World-fixed and path-parameter anchoring need later explicit profiles.

Geometry digest: token of `{profile:'owner-local-level-top-v1',frame:recipe.frame,shape:recipe.shape}`. Frame digest: token of the entire surface descriptor except frameDigest (including geometry digest, grid and semantic source anchor). Grid digest: token of the exact grid. Placed surface binding digest: token of `{ownerId,surfaceId,floorId,geometryDigest,frameDigest,gridDigest}`. It deliberately excludes cosmetic definition identity and owner pose: a supported finish/D4/move preserves local mark data when these source bindings remain identical. The owner binding still pins the exact current definition separately. Rendering binds that current source frame, owner pose, floor and footprint together; a captured stroke pose or a derived cell/UV cannot substitute for the current binding. Native world `[x,y,h]` becomes render `[x,h,y]` once. Origin.h already includes native floor height; validate the floor identity/elevation without adding it again.

A mark targets owner/surface/floor/binding digest and one named ordered layer. It saves explicit artwork pin, local metre TRS/pivot/mirror, opacity, linear RGB tint, mask and stable ordinal. Clean owners have no surface/mark records and no blank texture allocation. IDs and ordinals are unique within their declared scopes. Up to eight ordered layers are proposed; order/opacity changes are explicit source. A `stamp` has transparent support outside its finite frame; `wrap:clamp` only controls edge taps inside that support. A `detail` repeats within its own frame, clipped by its mask and owner surface; it never repeats the atlas page. Both clip to the actual owner surface, holes and selected mask, never neighbouring owners/floors. These are required provider semantics, not implemented presentation.

Masks are either the whole actual surface or bounded authored-grid RLE rows/spans. Grid origin/cell size/version are source, independent of derived cells, triangles, GPU instances or streaming chunks. Rows strictly increase; spans are sorted, positive and nonoverlapping; total covered cells are bounded. Negative integer coordinates are permitted within declared limits. Logical authoring chunk IDs partition saved marks and are not runtime chunk addresses. A source geometry/grid/frame/floor change cannot silently stretch, drop or retarget marks: explicit preserve-identical/reanchor/delete decisions cover every affected record in the SAME transaction. A floor change updates every retained target binding explicitly. Old and new spatial/semantic dependencies and locks remain relevant.

A multi-owner stroke is one finite group with explicit targets on one declared floor. `capturedPhase` is historical construction data: shared floor-plan graphic phase plus owner pose digests produce equivalent local transforms at creation. It is not ongoing world-fixed paint. Marks follow owners afterwards; moving one owner can separate the physical seam. Every non-null mark groupId resolves to a group that reciprocates that mark exactly once; every listed member reciprocates, with the same floor/artwork binding. Editing a group requires all members or explicit detach. Provider and headless implementation must prove the conversion/continuity before adoption; current examples do not claim a rendered seam.

## Resource and appearance requirements

Artwork.body contains immutable `blob` plus mandatory `imageView`. blob binds exact encoded SHA/byte length/media type/dimensions, sRGB and straight alpha. imageView.pageDigest is token(the entire blob descriptor). Its finite frame explicitly saves ID, `[x,y,width,height]` in integer top-left page pixels, `origin:top-left` and `imageTop:local-positive-v`. Its sampler explicitly saves `linear-premultiplied-bilinear-frame-v1`, alphaFloor8, no mipmaps, transparent stamp support and repeat-frame detail policy. Require positive frame sizes fully within the bound page. None of these fields may be inferred from IDs, requires lists or extensions.

The explicit thirty-row Artist-to-Core mapping in examples/artist-import-mapping.json reads fixed Artist `f5bfda9ec0f639018ccfee2415b1f70502e77cae` Git objects, maps each exact artwork/resource/version/hash/frame tuple to a Core `{id,revision,contentDigest}` pin, and carries explicit size/pivot/opacity/linear-tint defaults. Organic alphaFloor8 is2; road is0. Original resources.json, PNG bytes and full provenance notices are unchanged; the manifest SHA and original input paths are recorded. Thirty frame records share two immutable pages. The older borrowed whole-page atlas remains a separate example, giving31 artwork records and3 unique blobs. This tooling conversion is not an implemented runtime importer.

For each RGBA8 texel, zero alpha at or below alphaFloor8 **before** filtering/premultiplication. Convert sRGB RGB to linear (opaque RGB input has alpha1), multiply by alpha, then bilinearly filter four premultiplied taps constrained to this frame. Apply the explicit linear tint to filtered premultiplied RGB and multiply RGB/alpha by mark opacity. Source-over marks in ordinal order into an initially transparent layer; multiply the whole resulting layer's RGB/alpha once by layer opacity, then source-over layers in saved order. Two alpha.5 marks compose to .75; layer opacity.5 gives **.375**. Attenuating each mark by layer opacity would give .4375 and is wrong. Extra blend modes/channels remain unavailable.

For graphic UV `(u,v)`, pixel-centre coordinates are `(x+u*w-.5, y+(1-v)*h-.5)`. A stamp is transparent when u or v is outside inclusive `[0,1]`; otherwise its four taps clamp to frame texel bounds. A detail first wraps u/v fractionally and wraps each tap inside that same frame; masks and actual source clipping still bound coverage. From UV to owner metres: `position + R(rotationRad) * mirrorU((uv-pivotUV)*sizeM)`; mirror acts about the pivot before CCW rotation. Apply current owner mirrorX then quarterTurns then origin exactly once. Road text follows owner reflection, without automatic readability correction. No mipmap/atlas-edge bleed, implicit flip, world-fixed phase or neighbouring-floor projection is permitted. Sampling vectors are mathematical contract oracles, not shader proof.

PNG is the first required actual runtime decoder. Metadata and PNG signatures/IHDR checks do not prove a working bounded decoder; this C0 checkpoint implements none. WebP remains portable typed metadata but is **unbound** unless an actual optional bounded WebP decoder and its verified output/profile are supplied. No browser-native opportunistic decode or silent fallback. Decoder attestations bind verified encoded bytes, dimensions, alpha/colour interpretation and charged decoded allocations.

Durable resourceRefs is an ordered set of closed `{kind:'nautilus-artwork-resource-ref',version:1,artwork:Pin,imageViewDigest}`. imageViewDigest is token(`{blob:record.body.blob,imageView:record.body.imageView}`). Exact pins resolve only to Artwork records in the sole library authority. Sort by ASCII artwork ID then revision, forbid duplicates, and require exact coverage of retained library artwork: no missing, stale or extra descriptors. URIs, local paths, decode/readiness status, leases and second mutable descriptor bodies are not durable fields. The referenced immutable record provides the whole descriptor; no parallel mutable artwork authority exists.

Finite commands remain metadata only. Stage verified bytes and decoder leases through host resource ports outside operations[]. Portable pack metadata retains the frozen `blobEntries` and `blobs/<sha256>.png|webp` grammar, exact byte lengths and complete manifest/notices. Export's query produces a plan; complete export requires independently verified actual bytes. Import rejects bad paths/duplicates, sizes, hashes, unsupported profiles and incomplete dependency closure before one adoption. Generated review ZIPs reopen all three original PNG blobs; this is encoded-byte/header proof, not a runtime export or decoder.

The host may acquire immutable blobs/decoded resources before commit, but adopts references with the whole target only. Refusal/cancellation retires verified uncommitted leases. Unknown acknowledgement retains the complete potentially adopted resourceRefs set and its verified blobs/leases, including history/redo/pending obligations; it freezes overwriting edits/saves and reconciles the SAME request ID using the existing authority. A committed state survives display failure; retry presentation only. Resource deletion/GC requires confirmed unreferenced state across accepted source, history/redo, pending receipts and retained leases, never age alone.

## Commands, review and CLI

Thirteen edit kinds are listed in discovery.json. A command is one stable request ID, captured Expected source bindings, a finite flat ordered list of operations and one explicit budget profile. No nested batch, callback, arbitrary JS or data-driven plugin execution. The eventual strict input reader must reject duplicate JSON keys, nonfinite/negative-zero numbers, accessors, exotic/sparse objects, cycles and oversized UTF-8/node/depth input before planning. Operations stage in order against one private candidate; duplicate identities, stale references, a locked target, missing resource or unsupported feature aborts the whole batch. One accepted batch is one workspace history entry. An agent with host authorization can apply via the SAME service directly; it does not click synthetic UI buttons.

Proposed service: describe/snapshot/query/prepare/apply/cancel/recover. The proposed JSONL CLI keeps one persistent authorized host connection; UI calls the same methods with identical command bytes. Snapshot Expected fields bind actual accepted workspace/content/decorations/resources/profile/constraints/layout/catalogue/revision and authoritative context. Clients cannot manufacture accepted state by recomputing tokens after changing it. Context binds actual permissions, mode/epoch, finish/provider profiles and allocation/resource state.

Prepare borrows public v1 validation/repair for any active tile changes, with one finite request and no alternate solver. Decorative/library-only edits carry the exact unchanged tile source. It must bind resources, actual surface clip support and aggregate allocation limits before issuing a review. Review bindings distinguish source/target content, decoration, constraints AND resource-set digests, plus command, full source/target workspace, exact profile, presentation profile, resource lease set and allocation ledger. Target digest alone is not a lease.

Apply uses a host-owned opaque review token valid only on that live authorized connection, the original request ID and expected target digest. Serialized command/review JSON carries no transferable commit authority. Process restart requires inspect/reconciliation, not accepting a persisted token. Unknown uses committed:null and freezes writes while retaining resources. True/false/null outcomes and actual returned target/receipts must be independently checked in implementation proofs; expectation-marker mutations are insufficient. There is no copied CAS/journal/recovery factory in this proposal.

## Proposed costs and compatibility

Blueprint ceilings remain UNMEASURED proposals: eight layers/surface,4,096 marks/logical authoring chunk,1,024 resident marks across accepted/candidate/acquiring/unverified-retiring views,32MiB additional decoded artwork across actual allocations, with distinct copies charged. Artist ceilings join the same ledger:8 contributors per bin,32,768 aggregate bin references,4MiB derived buffers and4 atlas-page bindings. **One aggregate64 owned appearance-material ceiling covers existing finishes plus the compositor across all views**, not64 additional compositor materials. Existing totals remain two roots/50,000 triangles/1,024 cells. Hidden floors still count. An immutable decoded allocation can be shared only when the real provider attests the same physical allocation; otherwise count each decode/upload/copy, including actual padding/mips. Width*height*4 is a source-derived base RGBA illustration, not an upper bound on unknown provider allocations.

Discovery adds finite proposed packet/work/library/image/mask ceilings. Encoded packs are at most64MiB, source/manifest4MB, command1MB,1,024 operations,32 target owners and1,000,000 deterministic planning units. These are review proposals, not a public capacity or performance promise. CostBounds reports charged planning units, complete input/output bytes, definition visits, mask-cell evaluations, dependency edges and resource references separately from aggregate view costs. Charge copying/hashing, grammar/recipe work, closure, mask/anchor work, record allocation and serialization before the bounded operation; public repair retains its own unchanged step/spatial/geometry counters. The eventual loader must enforce complete UTF-8 bytes, finite data/depth/node limits before allocation, bounded dependency closure/work and actual resource ledgers. Refuse cap-minus-one or unavailable accounting; never prune source, skip a locked target or raise caps silently. The 480+480 illustration totals960 cells/marks and two roots, with a shared atlas's base RGBA allocation; no GPU/phone performance was measured.

Compatibility diagnostics proposed: UNKNOWN_VERSION, UNSUPPORTED_SOURCE_PROFILE, UNBOUND_SURFACE_CLIP, UNBOUND_RESOURCE_DECODER, CONTENT_DIGEST_MISMATCH, V1_RECIPE_ID_CONTENT_CONFLICT, MISSING_EXACT_REFERENCE, STALE_SOURCE, STALE_CONTEXT, LOCK_CONFLICT, ORPHANED_LOCAL_ANCHOR, INCOMPLETE_REMAP, MASK_OVERLAP, BUDGET_EXHAUSTED, NO_CHANGE, REQUEST_ID_REUSE and COMMIT_OUTCOME_UNKNOWN. Each includes bounded path/owners/action. None grants gameplay, support, navigation, physical damage or a public capability.

Immutable metadata evidence in candidates/tile-authoring/core/inputs/ is copied byte-for-byte from the named Git commits and verified by raw SHA. Standard Node tests use these copies, including the original777 schema, so shallow CI needs no worker branch fetch. Actual three-blob archive verification reads PNG bytes from the fixed Artist Git objects; no bitmap is duplicated in this role source. These evidence inputs are not a second runtime artwork authority.
