# Searchable building picker — 2026-10-28

The building library now uses a compact searchable dropdown instead of a persistent list. Opening the field shows the available buildings; typing filters names, styles and collections. The existing collection selector narrows those results. Selecting a result updates the current model, floor selector, reference links and downloads, then closes the popup and displays the selected name.

The control is an accessible combobox/listbox with an active descendant and explicit selection state. Arrow keys navigate, Enter selects, and Escape closes while restoring the current name. Tab and an outside click dismiss the popup. An empty query shows all available entries; unmatched text explains that no buildings match. The popup scrolls independently and fits narrow screens. Typing after Escape starts a fresh query rather than appending to the selected building's name.

Review covered all 48 options, live filtering, collection filtering, pointer and keyboard selection, focus retention, closing behavior and empty results. A 390 px touch viewport passed opening, selecting and bounds/overflow checks. The normal 3D gallery passed these interactions without JavaScript or resource errors. Repository checks passed: 29 local tests, 32 pinned-upstream tests, integrity checks and build.

The live Codex in-app browser exposed an existing renderer failure: WebGL2 context creation is disabled in that browser session. Previously this aborted the entire page before the picker initialized. The gallery now checks context availability and provides floor plans, floor selection and downloads when 3D is unavailable. It explains the limitation and disables unavailable 3D controls. The fallback was verified in the actual in-app tab and in an isolated missing-context case, including a second-floor plan and updated model links. Full 3D behavior remains available in a browser that supplies WebGL2.

Integration handoff: the dropdown component is `apps/buildings/building-picker.js`, imported only by the library app. The normal build copies it with the other app files. This work builds on catalogue commit `ee7c18ecdc2669168247b94a82156634b2c4ffe5`; menu commit `341711d656f582931c4bd6041578a33fd300695e` is followed by the browser fallback. Take the final art-branch head for both changes. The fallback handles context creation failure at startup; recovery from a context lost during an active 3D session is outside this change. Renderer/prefab consumers retain the catalogue's existing geometry, material and explicit game-adapter boundaries.
