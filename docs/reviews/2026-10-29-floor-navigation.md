# Floor navigation UI review

Prepared from reviewed main `ddfd43cf4b156eeb82b5c27772fe977ec10b0633`, following [the height plan](../extended-height-plan.md). Scope: a headless floor controller, optional DOM/painted view, explicit legacy-editor binding, six-/thirty-two-floor reference and focused state/input/browser acceptance. No donor bytes, schemas, game pins, root exports or automatic editor initialization change.

**Accuracy.** Prefer explicit floor identities and native `elevationM` records over deriving floor numbers by rounding model height or assuming a universal story interval. The view accepts unequal/negative native elevations and nonnumeric labels; the host decides which floors exist. The inherited editor retains its six available layers, including the special fringe/high-terrain role. Its 2.12 m renderer pitch remains an explicit adapter mapping. The thirty-two-floor cross-section is a navigation reference, not collision, perception, traversal, migration or tall-world evidence.

**Efficiency.** The controller holds one copied list and two small subject records; the view reuses five label buttons. Updates occur on host/input events. There is no simulation loop, timer, dense tile allocation or per-frame tracking query. Window lookup is linear in the supplied floor count; wheel gestures latch until an explicit timestamp shows an idle gap. These are code-based observations, not device/frame-time measurements or a claim about tall-world simulation cost.

**Narrative.** For authoring, recommend deliberate manual controls and cancellation feedback: changing the view must not finish a wall onto another plane. For gameplay adapters, recommend explicit character-follow and eligible-contact inspection with immediate disarming on detection loss. Manual inspection stays where the player puts it. Five painted labels keep the control compact and use the existing workshop's green/brass Farmyard material; this is a usability/aesthetic judgment supported by the captured desktop/phone view. A host still owns camera motion and whole-building/cutaway policy.

**Compatibility and adoption.** The headless boundary uses `{id,label,elevationM}`, so Coder's pinned `{id,index,label,elevationM}` records can be passed without importing worker state. The module has no hard-coded thirty-two-floor capacity. Available range and native heights are host data. Root owns package exports/build wiring and the editor installation call. Gameplay follow is demonstrated by host reports, with no AP, stamina, movement, targeting, visibility queries or clock dependency; it is not consumer adoption.

**Acceptance.** Twelve deterministic tests cover real IDs, five-label windows, 9→10/15/ends, cancellation ordering, veto/error paths, confirmed character floors, manual persistence, detection loss and late reports, focused-input key guards, normalized/latching wheel input, immutable data and disposal. The browser runner covers actual DOM focus, selector/scene wheel scope, phone touch/320-pixel targets, reduced motion and 200%-equivalent reflow. A built-editor check installs the binding explicitly, changes floor during a real wall stroke and verifies unchanged map/revision after pointer release, then checks native select synchronization and phone manual controls.

Frozen source/build acceptance, screenshots and helper cleanup receipts are recorded under `docs/reviews/evidence/floor-navigation/` after the delivery gates. No preview service is retained. The actual legacy workshop remains unmodified until root installs the binding; the reference remains independently usable.

**Separate baseline finding.** The first built-editor stroke probe selected the angled-wall tool and returned `Unknown wall-run material.` before a floor change. In this reviewed baseline, the shared options spread in `tools/editor-roof-adapter.mjs` places `roofTools.options()` after `wallTools.options()`, so the default roof material `slate` replaces wall material `wood`. The exact wall form constructs its own options. This is an existing toolbar composition defect outside the selector tranche; no donor/root adapter is changed here. The floor-cancellation acceptance uses the standard wall brush and still requires a valid preview before changing planes. Root integration should scope roof options to the roof tools or give each tool its own option namespace, then add a dragged angled-wall regression.
