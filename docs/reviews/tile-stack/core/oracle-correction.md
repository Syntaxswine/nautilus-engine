## The corrected proof boundary

The previous oracle could compute plausible intervals without binding that computation to the actual reported preparation outcome, returned target, next constraints or finish inspection. Its expectation-marker mutations did not establish rejection of forged successful output. This was a proof defect, not a runtime correctness finding.

The replacement independently derives the intended recipe/owner source, original controls, native floor placement, anchor subsets/locks, explicit source deltas, direct changed owners and old/new closure from `input.bundle`, accepted constraints, exact profile and finite intent. It does not import the engine or helper. Decimal source arithmetic produces q1e6 integer bounds. All original source and reservation contacts are enumerated without a height filter. Saved per-pair stronger requirements are retained; draft clearance applies only to pairs touching independently derived direct changed owners.

That model is compared with the actual bound plan request, next constraints, every explicit binding digest, closure/discovery and the complete old-and-next obligation multiset. Original recipe descriptors, unused recipes, owner identities, anchor subsets, source extensions, floor table, revision, selection, joins, relations and content/catalogue/layout hashes are checked in the actual successful target. Overall/public success flags and the presence/absence of a target must agree with independent geometric/contact coverage. `plan.ok` may be true when public preparation correctly refuses; the oracle does not equate those two flags. Fixture expectation markers remain additional assertions only.

The proof artifact's private format is version 2; no public API/schema changes. Each case records the actual `publicRequest` separately from the bound plan. In `missing-one-crossing`, the valid 105-relation plan remains intact and bound; a labelled `omit-one-crossing` fault submits 104 relations to the public core. The oracle verifies that exact permitted wire difference and independently detects the uncovered intended contact. It never takes a damaged request as the definition of intended geometry or constraints.

Additional controls cover a false public refusal of a valid positive and a false stronger minimum in lower-pair inspection. The checked-in interval-oracle.json records each actual rejection code. These are fixed deterministic modifications of the acceptance fixtures, not a new stochastic campaign.
