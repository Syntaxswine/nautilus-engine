## Rules and initial balance

The ordinary `farmyard-percent-1` profile uses the existing `skill:null` attack path: dexterity accuracy, clamped 5–95 percent by existing rules, with no new melee stat. A rolled hit is separate from actual current-world contact. Explicit named modes select `blunt`, `piercing` or `slash`; mixed weapons expose separate modes. Unknown types refuse. The default strength-linear profile is `round(base + strength * coefficient)`, tunable through explicit persisted multipliers. Sword slash is `round(8 + .30 * strength)` for 1 AP/4 stamina, 6 windup + 3 impact + 7 recovery ticks. The two-handed hammer is `round(16 + .60 * strength)` for 2 AP/10 stamina, 12 + 3 + 13 ticks. Every tick is 50 ms supplied by the retained game. Other values are discoverable in the frozen equipment catalogue. These are straightforward initial balance choices, not claims of physical realism or playtest balance.

Agility controls existing max AP, endurance existing max stamina and its single existing damage-resistance application. The optional `typed-flat-v1` armour profile requires all three explicit reductions; armour is subtracted from raw damage before calling the old endurance-resisting damage function once. Without that explicit optional profile, damage type remains visible but gives no invented resistance. No skill, class, species or character schema is added. Resource loads never refill damage or normalize spent budgets.

## Ownership and conservative contact

The host binds a selected target body, world/floor identity, current source/target positions, headings, radii and heights. At the first impact tick, the profile checks the near side of that selected body against named reach, source-facing cone, floor and height band, then asks the host for current wall clearance with matching world/body revisions. There is one contact sample, one possible target and one seed step per accepted contacting or missed swing. A target moving away, wall, height or rear arc can turn a rolled hit into no contact while the committed swing still spends its costs. Presentation markers never grant an impact. This is a conservative tactical approximation, not swept native weapon-mesh physics.

An explicit directional guard uses current defender facing/height coverage. Wood, metal, tower and riot profiles declare distinct arcs, body-height coverage, upkeep and block costs. A full physical block requires a contacting rolled hit and affordable unreserved stamina. Upkeep/block failure explicitly breaks guard. A shield mesh alone grants nothing. Attack reservations, attacker fees, defender upkeep/block fees, HP, guard state, tick, seed and receipts are staged together, including a fighter who both attacks and guards. Two-handed hammer, spear, halberd, bow and crossbow cannot also equip a shield. Switching/stowing is an explicit command and invalidates guard/action state.

Pre-impact interruption is free, releases the reservation and incurs recovery. Lost permission/ownership, incapacitation or missing impact budget stages a named cancellation/recovery with no roll or HP change. An interrupted or already committed impact cannot resurrect on late presentation or reload. Identical full command retries return the saved receipt; ID collisions refuse. A pre-commit query/persistence failure leaves all participants and the clock unchanged. An animation failure after publication remains committed and cannot replay damage. Keep all read-only query dependencies covered by the retained host revision.

## Accuracy, efficiency and narrative decision

For this reusable first melee boundary, selected-body/cone/height plus a current host wall trace is preferable to either a pure probability roll or full mesh collision. It models walls, distance, height, current facing, directional guard and moving targets while retaining the existing probability profile. It omits detailed weapon shape, multi-target sweeps and continuous hit timing, so it is less physically exact than a complete swept collision system. Efficiency is a code-based estimate: at most eight bound participants, one selected contact query per due impact, no renderer in rules, no simulation timer, and a bounded ledger. Browser proof names its software renderer/device/workload; it makes no FPS, hardware-GPU or performance-saving claim. Narrative remains game-selected through original painterly native-scale weapons/shields and explicit attack modes. The portable existing probability profile remains available unchanged; richer physics is deferred unless a game's needs justify its cost and ownership contract.

6. Run the bounded Night Ledger fixture via `node tools/fantasy-melee-entry.mjs --source`, serve the project and open `/artifacts/fantasy-melee-source/`. Its single host clock owns UI input advancement and rule steps; player UI owns WASD/touch walking. The fixture owns a small flat yard, one explicit wall, roster inventory and save key. The existing inherited fixtures/schemas remain available. Bow/crossbow controls are equip/draw/load proof only.

The fixture's `createMeleeYard` illustrates a synchronous whole-record persistence hook. A production storage adapter needs an equivalent atomic transaction with compare-and-swap for all retained records; a series of independent writes is not this contract. Its free flat-yard locomotion is a declared fixture policy, not a replacement for consumer movement rules. There is no automatic resource regeneration. “New duel” explicitly replaces the encounter; save/reload preserves injured HP, spent resources, action progress, reservations and seed.
