# Smart Tile Editor reference host

The isolated entry is `examples/smart-tile-editor.html`. Build with `npm run build`, serve the static output with the existing `npm run serve`, and open `/examples/smart-tile-editor.html`. This entry does not mount new controls in the inherited map workshop. Stop a manually started server with Ctrl+C when finished.

This is an Editor-local first proof: Rectangle, isolated level Path and Finish whole surface, with explicit Review then Apply. It uses the actual public tile resolver and canonical native surface presenter. The retained original map is read-only; authored tiles are a sibling complete canonical v1 bundle. No C2/private evaluator, Boolean union, geometry Paint, graded path, collision, support, navigation, fire/water service or game adoption is implied.

## Construction

Use numeric controls and Update draft, or drag on the canvas to create a draft. Review prepares the public-core result and its native surface without changing the accepted document. Apply accepts the current one-use review. The canvas Enter key requests review only; native buttons retain Enter/Space activation. Alt/right-drag orbits, and the canvas wheel zooms.

For the acceptance yard, create an 8 × 4 m rectangle at X=20, Y=20 with seed 0. It crosses the actual source-map 24 m sector seam. Add the same rectangle at X=28, Y=20: the core supplies one supported straight join. The identical descriptors can share one recipe. Select the neighbour and use Review owner lock then Apply. Select the first owner using the whole-owner list or the actual surface/derived cell in Select whole owner mode. Finish with `skin.slate` or `skin.sandstone`; `skin.painterly` is also bound. Only the selected owner's interior recipe is changed. Canonical boundary paint and the locked neighbour remain unchanged.

Path retains original local line, arc or cubic controls, a constant width and an explicit uint32 seed. This proof requires level local controls at h=0. It does not reconstruct controls from sampled meshes. Dragging creates a new line or moves the origin of the currently staged arc/cubic; numeric controls remain available for exact values. Unsupported contours, reversal, grade or repair coverage refuse with named diagnostics and preserve the accepted source/history/view.

The supplied native Editor profile has three available floor records: IDs `0,1,2`, labels `1,2,3`, elevations `0,2.12,4.24` m and explicit original-layer bindings. The existing floor controller/widget displays up to five available labels; no extra floors or character/contact services are fabricated. An isolated surface can be placed on the supplied upper floor. Floor **or mode** change retires input and tickets before the drawing plane changes. Existing form/dialog guards and one-step wheel/key behavior remain owned by the real floor widget.

Stacked construction is outside this workflow. Public v1 can express vertically separated decks with explicit measured cross relations; this Editor does not author that stack intent or manufacture relations to bypass a contact refusal. It also does not add floors beyond the complete retained source's available layers.

## Checkpoints and history

The first source is a complete original 240 × 240 portable map, including all original arrays and unknown bounded metadata. Its JSON string is retained verbatim. Validation never replaces it with a normalized map. The default visual underlay is that blank yard; this reference is not a general-purpose renderer/importer for arbitrary legacy map contents.

One isolated localStorage key, `nautilus-smart-tile-editor-proof-v1`, holds the entire authoritative checkpoint: original source, supplied floor table, canonical bundle, write-ahead operation and settled receipts. Stage writes retain the accepted document. The final native synchronous write atomically changes the bundle and appends the original operation's receipt. All operations, including Undo/Redo, use that same authority and the existing resource-free serialized-history algorithm.

History is session-only: at most 64 combined Undo/Redo entries and 16 MB. Failed preparation or acquisition preserves redo. Saving emits the complete checkpoint verbatim; reopening the **current authoritative checkpoint** validates and acquires before starting empty session history. Historical/foreign files receive `CHECKPOINT_AUTHORITY_MISMATCH`; use a separate explicitly owned session/authority to inspect another complete checkpoint. This proof never resets a durable journal to restore an old file.

A throw/nonboolean storage acknowledgement is unknown. Editing, Undo/Redo and overwriting saves/opening stay frozen until the **same original request ID** is reconciled against authoritative storage. A matching committed receipt adopts its target/history once; an exact unchanged before/pending record can settle refusal. Divergence remains frozen. Reloading a pending record preserves its original request for recovery. An acknowledged acceptance stays committed after later display/observer failures; Retry accepted preview rebuilds presentation without replaying CAS/history.

Legacy/block/game exports remain disabled with explicit preserving explanations. This wrapper is not a public engine save schema or consumer capability, and no game pin changes.

## Ownership and budgets

The Editor owns one canvas gesture recognizer. Ownership is fixed at pointer-down. A second finger cancels and consumes the entire sequence until all pointers lift, including its subsequent click events. Tool/ticket changes retire the input owner synchronously. Blur, hidden document and capture loss cancel construction; old releases cannot resume a stroke. The UI panel owns numeric controls/DOM only, and the borrowed floor widget owns floor interaction. Neither creates history, persistence, matching, a camera router or another floor authority.

One acquisition can be in flight with one coalesced latest intent. Accepted, candidate, in-flight reservations and unverified retiring allocations share a total budget of two roots, 50,000 triangles and 1,024 derived cells. Retiring resources keep their budget until verified. Actual public-provider disposal drains all owned geometry despite throwing listeners, preserving borrowed Three/materials/maps and unrelated neighbours. The host disposes its own material pool only after session retirement.

The resolver is bounded to 32 authored owners/recipes, 256 repair steps, 32 closure owners, 100,000 spatial tests and 100,000 repair geometry work units. These are proof budgets, not world limits or phone performance measurements. Readiness separately reports authoring, shape, confirmed/candidate visual revision, and unbound query/support/navigation/fire/water/game services.
