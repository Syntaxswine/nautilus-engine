# Mount Dora content and authoring

This optional intake supplies the complete pinned town catalog, a native authoring facade, an engine walking host and a shared-Three presentation. It does not adopt Nautilus into a donor game. Town data and upstream rendering dependencies are a separate opt-in resource package, outside the four default SDK payloads.

The source is Farmyard Realtime commit `8395204ce6b60aa20cc8936fc89fe4a40192920c`. The handoff note is at `46d981e2021150700e3184b4f49b6364531a4556:docs/maps/mount-dora-handoff-8395204.md`. The reviewed archive is 27,852,653 bytes, SHA-256 `ad5880f74521c5971afc24282d2a950e7866f661c3f8ef7f5cb13ba0fc50ef2c`. Its 1,334 source-manifest entries were verified once against immutable Git objects. The selected dependency closure is recorded, byte-for-byte, in `vendor/mount-dora/8395204ce6b60aa20cc8936fc89fe4a40192920c/source.json`; it includes original notices. The importer reads Git objects and never changes the donor worktree. Original files have an `.original` suffix; executable adaptations are generated separately with their own source/output hashes and change ledger.

## One native editor authority

`createMountDoraCatalog(project)` supplies detached sector descriptors. `openMountDoraDocument(input,{catalog,reference,placements,presentation})` opens a verified land sector through one retained public `MapDocument`. Preview, apply, rename, replacement, undo, redo and export delegate to that document; there is no second editor/history. Deterministic character metadata is supplied only when absent. Existing guard weapon/patrol/character edits are retained; original guard evidence is recorded separately.

`mountDoraEngine` keeps source commit/art identity, source metadata, source-native hash, original guards, complete source placements and explicit presentation profiles alongside current edits. Tree records, source metadata and original placements are protected. Exports/reopens retain them. `nautilus-mount-dora-content-v1` is a required consumer capability. Legacy blocks, block capture/replacement/rotation and connected block generation refuse this envelope before losing its global source/placement identities.

The live world stages native geometry before the editor commits. `world.stageNative(candidate)` returns either a refusal or a single-use `commit()`; a stale actor/geometry revision refuses. The host commits its real document and the prevalidated world projection together. Failed edits preserve the current map/world/history. Ground edits, new wall runs and guard metadata are supported. Changes to source art-backed building shells or upper masks are explicitly refused: those need a corresponding part/art adapter, rather than leaving a stale model or collider. Stairs, grid edges and other unbound native features likewise refuse. Headless authoring can retain/export a complete sector for a consumer with additional bindings.

The reference UI uses this same authority, including an actual wall edit that changes rendering and walking, undo/redo and reopen. Large sessions use Nautilus-specific transactional IndexedDB, not localStorage. Changing location/presentation starts a new study; explicit Reopen Saved restores the exact saved study. Do not interpret validator markers as geographic player starts.

## Supported walking and state

`walkSupportedActor` is separate from unchanged flat `walkActor`. It uses bounded provider-planned paths and full accepted-path body/support queries. Its physical three-dimensional distance budget consumes actor speed × explicit elapsed seconds; it retains a partial step rather than snapping, replaying time or teleporting to a nearby floor. A changed heading first completes the current retained step (or reverses it for opposite input), then replans any remaining distance at the supported endpoint. Perpendicular input cannot strand an otherwise unobstructed actor mid-riser. Host-owned travel receipts retain the exact path, progress, floor, policy, geometry key and actor/world revisions. Actor wire fields remain unchanged. The host saves actor, receipt, content/policy identity and resources atomically. Missing/malformed/stale bindings refuse without mutation.

The reusable default `natural-eighth-story-v1` permits at most 2.12/8 = 0.265 m up/down. Mount Dora explicitly selects `mount-dora-source-deck-v1`, permitting its original 0.4 m deck approach. That compatibility profile preserves source deck-overlap/native bridge-cell rules and water rejection. Foot elevation uses `deck.heightM`, not the millimetre render bias in `deck.topM`. The 0.4 m value is a raised deck/body-root position, not anatomical actor height. The review actor is 1.8 m high with a 0.23 m radius. New Donnelly approach risers are 0.212 m and work under the natural policy.

`createMountDoraWorld({project,runtime,baseURL,fetcher,...})` binds verified opt-in resources to ordinary engine actor/pose/scene/walking endpoints. The supplied runtime does not include the donor activity/application. `createMountDoraSurface` is a shared-Three surface used by normal `mountPlayerSetup`; standard input, camera, UI, native actor, confirmed-distance gait and clock remain their existing services. The town panel occupies the standard map slot, which registers its HUD exclusion and camera-safe rectangle. The source decoder is exposed as a read-only render/query facade; native changes use the staged document path. Renderer eviction/cutaway never decides support or collision. Open pitched roofs use a conservative minimum-eave overhead band across their filled footprint; this host does not provide rooftop traversal.

No geographic entrance is verified by this content. Buildings remain closed unless an explicit derived profile supplies the corresponding physical parts. No decorative door button is provided. Any future verified door must bind standard production interaction, clearance, cost and persistence contracts. Guard weapons and patrols remain metadata; combat, AI, cast/turn policy and game-specific brush/cover decisions are unbound. Source brush-depth queries and visual cutaway remain available. This is not a complete Farmyard combat operation.

## Bounded presentation

Detailed visual residency is a 3 × 3 window of 24 m blocks. Native decoded data has its separate bounded nine-sector cache; actual actor sectors stay pinned independently of view changes. Unloaded authoritative terrain refuses movement. A source-derived 16 m distant overview adds 9,450 flat visual cells in nine instanced material batches. It prevents a hard terrain edge in neighborhood/overview views, approximates distant boundaries, allocates no additional decoded sectors or tree models, and has no support/collision authority. Exact native terrain takes over nearby. No scene creates all 17,171 detailed trees at once.

Ordinary `engine-muted-v1` finishes select stable cream/ochre/sage tints by building ID, subdued roof values and deeper glazing. Footprints, envelopes, shared walls, courtyard voids and openings do not change. Existing painterly textures are reused, with no new bitmap art or global lighting/tree changes. Protected landmarks do not receive this uniform cosmetic profile.

Donnelly House `osm-way-547799531` is distinct from the protected depot. `photo-guided-v1` rebuilds its exterior within the mapped horizontal envelope: two 2.12 m main storeys, open roofed verandas, 0.848 m porch floor, four natural risers, three-storey faceted tower, curved/flared cap, front gables, tall windows and a dominant upper-wall oculus. Dimensions/pitches and unseen treatment are inferred from the supplied exterior photo, not surveyed. The same versioned part graph supplies render, support, body and overhead geometry. Opaque source collision is suppressed only under this explicit profile. Roof cutaway changes presentation only. Reusable porch, riser, profiled-cap and gable parts remain bounded. The original source-compatible model stays selectable. User reference photos remain ignored local evidence and are not published.

A later required under-porch check found two gable windows remaining visible after their roof was cut away. Their panes and frames now share that roof’s cutaway role; exterior geometry/materials are unchanged. This adds one material/role batch (12 meshes total; still 6,372 triangles and six materials).

## Rail connection boundary

The source railway is disused. Original representation remains under `source-compatible`; `connected-study-v1` reconstructs the omitted branches at shared OSM nodes 4977559644 (B04) and 4977559639 (C04). Original gaps measure 17.9986 m and 17.5515 m. Incoming-to-branch angles are −6.1884° and +3.7209°; branch versus departing main is −6.3200° and +6.5854°. These are measured source bearings, not catalog 45° approximations. Only the connection rails are added; underlying road/ground data is retained and no bridge is invented.

The additive `surveyed-v1` route profile retains finite measured waypoints, tangent curves, exact anchor snapping and the actual shared throat station in either main ordering. Version 7 portable routes require `nautilus-railway-surveyed-v1`. Legacy compass/grid routes retain their behavior. Actual offset-rail intersections place shallow crossing fittings; timber extensions follow the measured divergence. Nonjoining diamonds retain independent routes, exact measured intersection points, signals and occupied-state saves. Current measured diamonds support 45°/90° fittings; other crossing angles refuse explicitly.

The existing rail editor and train-preview/traffic authority drive two separate operating studies, one for each join. Their straight approaches are extended for train clearance and clearly labelled as a study. Main/branch choices, reverse/branch departures, occupied-switch refusal and exact saved traffic are checked. The current single-turnout route contract does **not** provide an end-to-end drivable two-turnout town passing-loop network. No consumer pin is updated.

## Accuracy, efficiency and narrative decisions

| Difference | Evidence and preference for this intake |
