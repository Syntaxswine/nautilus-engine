# Private C2a rectangle composition

Approved base: `3f602272a3a2ecbe4ade0d33773a0e4f52da0706`. The Architect approved this bounded headless tranche on 2026-11-01. It extends the private `packages/tiles-core/candidate-v2.js` only. All 18 accepted v1 runtime/schema files, public exports, registry, capability identities, whitelist, version and consumer pins remain unchanged. No renderer, Editor or game adopts this candidate.

C1 remains a mathematical root inspector. C2a adds independently placed owners, full internal source intervals, saved finish precedence, exact primary-reservation certificates and one complete-bundle pure preparation. It reuses C1 arithmetic, segment arrangement and sector/component/void topology. A bounded grid partition derived inside that same compiler retains all owner labels on the supported rectangles; it is not another Editor resolver.

## Explicit source

A v2 layout may retain this optional typed field:

```json
{
  "compositions": [{
    "kind": "planar-composition",
    "version": 1,
    "id": "paving.surface",
    "operation": "union",
    "profile": "level-rectangles-c2a",
    "members": [
      {"instanceId": "courtyard", "primaryReservationId": "body"},
      {"instanceId": "walk", "primaryReservationId": "body"}
    ],
    "finishOrder": ["walk", "courtyard"]
  }]
}
```

`finishOrder` is a complete permutation, highest precedence first. The original recipes and layout instances remain authoritative and independently editable; every contributor survives even under another finish. Geometry membership, winning cosmetic skin and physical boundary material are different facts. Source IDs, anchors, controls, placements, seeds, locks, unused recipes and pinned templates are retained. Annotation strings have no functional meaning. Empty membership is permitted for an explicit empty composition; a complete catalogue still contains at least one retained recipe. Omitted/empty `compositions` preserves existing group-free A/B source/digest behavior and unresolved gates. Opening an older save never adds a group or upgrades it.

The first profile accepts exactly one group, at most 16 members, and at most 32 total rectangle owners in the selected complete layout. Used recipes may be v1 or v2 original region records with one exactly closed compound of four native axis-aligned lines. D4 and translation are applied as rational affine operations on the original binary64 values, without an intermediate Number addition. Every used owner has four complete distinct straight side ports, exact widths/midpoints/thickness, explicit floor binding, constant upward normals, no route flow and one full boundary material interval. Group members have open ports and share exact base/thickness/floor/channel/layer and compatible complete material/profile/sampling/UV contracts. Unsupported used source refuses; unused future grammar is retained, not evaluated.

Each named primary reservation must equal its owner's actual rectangle footprint and vertical interval. Adjacent and overlapping member primary reservations receive individual exact contact certificates. Positive area is occupied once; multiple region outlines are never misinterpreted as a union. Internal boundaries, coincident contributors, point-contact sectors, components and full void outer adjacency survive. Point contact does not create traversal.

All additional reservations and all external contacts require their own full straight joined-boundary or measured cross/alongside proof, or refuse. No group/relation/transition tag waives an owner pair. Existing required ports outside the group require actual full matches; terminal ports never join. Partly occluded full external joins refuse. Native coincidence is checked independently of q1e6 canonical samples.

## Candidate use and host preparation

`compileTileLayout(layout, actualCatalogue, {profile, limits})` and `openTileBundle(bundle, {requireResolved:true, composition:{profile, limits}})` may resolve only this explicit profile in the private candidate. Omitted options capture the approved complete default limits. Group-free/native shape compilation, general v2 matching, cell derivation, requirements and public registration remain closed. A v2 recipe's generic compile status is still unresolved; C2a evaluates its supported original rectangle only within the explicit complete-layout profile.

Compiled mode is `rectangle-composition`. It contains exact root topology; occupied rectangular partitions with all owners, winning owner/skin and exact area; every internal/external atomic interface and original source interval; both owner's canonical port copies; full joins; specific primary reservation certificates; and complete source/context bindings. Port bindings distinguish geometric exposure from finish visibility. Source port intervals partition [0,1] exactly. Their IDs and native span keys survive cosmetic copy-on-write; shared keys exclude incidental owner/recipe/skin identity while retaining actual canonical geometry, semantic profiles and UV. Partial spans do not invent a common refined schedule: `renderPlan:null`. Exact rational spans may need refusal in a future q1e6 projection; this checkpoint provides no C2a renderer projection.

Pure `prepareTileRepair` / `prepareTileEdit` uses one finite complete candidate, with no alternative search:

```js
const result = core.prepareTileRepair(acceptedBundle, {
  kind: 'planar-composition-edit', version: 2,
  profile: core.TILE_COMPOSITION_PROFILE,
  id: requestId,
  expected: {revision, layoutDigest, catalogueDigest, contextToken},
  editedOwnerIds, finishCopies, nextBundle,
  limits: {...core.TILE_COMPOSITION_LIMITS}
}, {contextToken, cancelled: false});
```

Every source/binding change is explicitly listed. The candidate is a full self-contained bundle at exactly one newer revision; old recipes are not pruned and existing floor definitions are retained. New descriptors need increasing content versions. New recipes must belong to a candidate owner. Complete old/new geometry, semantic/spatial closure, every port/contact and conservative whole-owner locks are checked atomically. No partially resolved `next` is returned on failure.

Finish changes use a fresh recipe ID from `tileCompositionFinishRecipeId(requestId, expected.layoutDigest, instanceId)` and an explicit `finishCopies` entry `{instanceId, fromRecipeId, toRecipeId}`. Copy the complete old recipe, changing only its ID and `interior.skinId`; repoint only the same unlocked instance. Bound controls, local IDs, seed, anchors and physical contracts remain exact. No mixed geometry/finish operation, shared in-place cosmetic mutation or hidden catalogue garbage collection. The 128-recipe inherited ceiling can eventually refuse more copies; it is not silently raised.

A locked owner's complete source/binding and exact visible coverage are protected. Adjacent edits may use its unchanged full boundary. Covering it with higher-precedence overlap or changing its winning region refuses even if its source bytes are unchanged. This preparation does not implicitly unlock an owner.

The candidate `createRetainedTileConsumer(host)` has the same read/prepare/one-use-handle/final-lease/CAS contract as the frozen v1 factory; its private dispatch calls the one candidate core preparer. A normalized-source parity assertion keeps that factory's lifecycle logic identical. The host supplies actual source/context tokens and owns storage, checkpoint schema, durable request journal and history. An Editor-shaped conformance fixture retains original raw map JSON beside the tile bundle, one CAS/history entry and unchanged redo on refusal. That fixture does not define a public Editor checkpoint format or give core map storage/history/cast/clock ownership.

A lost/invalid CAS acknowledgement returns `COMMIT_OUTCOME_UNKNOWN` with the same request ID. The host freezes editing, Undo/Redo and overwriting saves until authoritative journal recovery of that identity. It must not guess rollback or retry under a fresh command ID. Prepared handles belong to one actual core connection and are consumed once; detached evidence is not a handle. Host context must include relevant current floor/provider/profile/mode fingerprints. A context change while acquiring a view invalidates the final host CAS.

## Ceilings and readiness

Whole preparation shares at most 128 original old-plus-candidate segments, 10,000,000 charged work units, 2,048 emitted partitions, 4,096 port bindings and 16,384 provenance links. Overlay topology/arithmetic retains the C1 ceilings; work/output/provenance are not reset for every owner or old/new child. At most 32 affected owners; no alternative search. Complete candidate artifact preflight is 4,000,000 UTF-8 bytes, separate from the inherited complete-bundle/plain-data limits. Callers may only lower ceilings. Input/source traversal, precharged catalogue/shadow sampler work including unused recipes, canonical child work, rational bit operations, sorting, membership, incidence, provenance, dependency discovery, hashing and serialization are charged or conservatively modeled before the relevant bounded allocation. Counts model work, not CPU instructions or device timings.

| Fact | C2a state |
| --- | --- |
| Original source/save/load | Retained, explicit typed profile |
| Exact level-rectangle geometry | Resolved within captured ceilings |
| Complete layout and pure preparation | Private candidate only |
| Renderer/preview | Unbound; ca285 is a separate public-v1 surface provider |
| Native classification | No new C2a query API; C1's root-only classifier remains separate |
| Physical query, floor contact, support, navigation, fire/water or game | Unbound |
| Public registration / Editor adoption | Architect review required |

Boolean arcs/cubics/fields, diagonal layout contacts, general region/DAG layout integration, varying widths, ribbon/section/cap/solid evaluators, mixed-level composition, graded surfaces, ramps/stairs and physical material/width/height transitions remain unsupported source, preserved and unresolved. Public-v1 isolated constant-width curved paths remain unchanged, with their existing distinct presenter and repair limits. A transition needs proved actual endpoints and reservations; a label grants nothing.

## Reproduction and design choice

Run `node tools/measure-tile-c2a.mjs`, `python tools/verify-tile-c2a-oracle.py`, `node tools/measure-tile-v2.mjs`, the independent eight-schema validator (with a test-only jsonschema installation), `node tools/test-tile-v2-package.mjs --candidate`, then the four required repository gates. Installed proof runs the same C2a tests and exports actual installed outputs to the independent Fraction oracle. The oracle independently derives coordinate-grid membership, finish ownership, all original atomic intervals/port coverage, exact primary contact intervals and component/void/sector associations, and rejects deliberate forgeries. Actual closure/file hashes, fixture counts and cleanup receipts belong to the checkpoint, not a performance claim.

Accuracy preference: original controls and exact labelled geometry preserve source-value alignment and independent edits. This is exactness in the binary64 source model, not physical calibration. Efficiency preference: one bounded core arrangement shared across ownership/contacts avoids a second Editor resolver; this is a code-based expectation. Exact overlay cost can be quadratic and copy-on-write increases catalogue size; phone/desktop timings remain future measurements. Narrative preference is subjective: reusable parametric families with shared alignment and owner-specific painterly finishes fit the expansive engine direction. Preserve legacy game profiles and choose richer simulation where a game calls for it. No simulation or consumer adoption follows from this headless proof.

All proof commands are foreground, short-lived processes. The offline installer verifies and removes its exact task-prefixed temporary stage/consumer in finally. This tranche creates no preview server/browser/watcher or retained helper.
