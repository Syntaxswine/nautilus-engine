# Public player composition and two-circuit yard

The optional `@nautilus-engine/map-core/player-setup` headless API and `/player-setup/browser` assembly are registered with `/native-actors`, `/native-actors/three`, `/player-ui` and `/player-ui/style.css`. Read the [setup guide](../packages/player-setup/README.md) and [native startup guide](../packages/native-actors/README.md). The headless core profile exposes only setup/native metadata and world preparation; it does not expose the browser setup, shared DOM UI or renderer.

`7f50cb2a48aef87a16fc0465997549be9ed88dc2` is the reviewed compatibility baseline used by the version 1 recipes, **not a claim that commit contains the new setup API**. The accepted new runtime is `62f2fe90210b10985f80d75d9e4425f424a51c6b`; current per-file source records and assembled package provenance identify its registration. Package version stays `0.10.0`. This integration makes no npm publication, release tag or consumer pin update.

The [real two-circuit yard](../examples/train-yard.html) uses the public assembly for ordinary controls, contextual boarding, driver/rider handoff, native player startup, presets, material/camera settings, keyboard/touch and HUD framing. Extra operators use public native startup. The retained game host still owns both routes, stock, station services, transactions, clock advancement, save resources and its original 1.6 m collision policy. Visual model dimensions remain separate. Application-specific checkpoint/help/service controls occupy shared extension slots; they create no second gameplay input path.

Yard v2 checkpoints contain the retained host, exact setup recipe/native player checkpoint and operator native poses. Reload stages a complete candidate while old input/time are frozen, releases original leases, and transfers ownership only after preparation. Failed/cancelled preparation keeps the accepted scene. Legacy `nautilus-train-yard-save` v1 checkpoints have an explicit load path: keep their exact retained state/resources, use current UI/model settings, and initialize native presentation without input or effect replay. Retained station services preserve their existing safe pause-on-restore behavior.

The Farmyard gait original is source-only under `vendor/farmyard-native-gait/279d2d34786b3e6e5c5baeeac6898e60030afdbe/`; its packaged notice/provenance preserve source hashes and purpose. Only the reviewed mammal adaptation executes, sharing the existing Three namespace. Data/paint remain at the original AFT pin. Normal distributions and static builds exclude the original reference JavaScript, source-only duplicate, Node tools/tests/fixtures and bulky review evidence.

The registration layer authenticates the accepted module/resource bytes and exact root/profile additions before passing named historical preimages to the existing C1/artwork/railway checks. Unrelated fingerprints and lineage remain enforced. Definitive package and real-scene validation are recorded with the integration handoff; phone emulation does not measure physical handset performance or a fresh builder's setup time.

Accuracy favors confirmed poses and retained query/command authority (code-based evidence). Efficiency favors one renderer, game clock and shared input owner; CPU/GPU savings are unmeasured. Farmyard contextual presentation remains the default and Tinderbox mechanical materials remain selectable for steam (subjective narrative preference). Both preserve action meaning. The larger modular Night Ledger test ground and objective verification are a later independent reuse task.
