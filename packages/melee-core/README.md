# Optional fantasy equipment and close combat

Public entries: `@nautilus-engine/map-core/melee` and `/melee/equipment`. Both are plain-data Node modules with no DOM, renderer, storage, timer or ambient random generator. The catalogue's `usageCard` points to `usage-card.json`; actual art is the separate `/fantasy-equipment-art` and `/fantasy-equipment-art/three` component. [Design, balance and host example](../../docs/fantasy-melee.md). [Playable Night Ledger fixture](../../apps/test-ground/melee/index.template.html).

This is the `nautilus-melee-training-v1` profile, definition version 1. Its explicit physical damage IDs are `blunt`, `piercing`, `slash`. Named modes carry their own reach (native metres), horizontal arc, body height band, AP/stamina costs and windup/impact/recovery ticks. The 15-item catalogue is frozen. Unknown IDs, modes, versions, damage types and unsupported draw/load operations refuse. Bows/crossbows have visual draw/load state and no melee modes or new ranged ballistics.

The host binds one to eight existing character-v1 records, current world/body/facing snapshots, an inventory query, permission query, current wall-clearance query and optional typed-flat armour. Create a separate `nautilus-melee-state` v1 sidecar with an encounter ID, immutable content compatibility pin and saved uint32 seed. It does not change character-v1, progression or map formats. `openMeleeState` preserves actual HP/resources and never refills or normalizes them. Completed results, original command payloads and random stream continuity remain in the bounded ledger. Limits are 512 accepted commands and 4096 durable events; finish an encounter explicitly, rather than evicting IDs and inviting replays. Saves are validated plain records, not tamper-resistant signatures.

`previewMeleeAttack` is an advisory, mutation/RNG-free snapshot query. `stageMeleeCommand` accepts a command ID and exact expected melee revision. Attack acceptance reserves AP/stamina and starts windup without spending them. `availableMeleeBudgets` exposes current, reserved and effective available amounts. **Every other resource action in the retained game must honour these outstanding reservations.** At each 50 ms host step, `stageMeleeTick` stages upkeep, cancellation, impact, costs, seed, HP, guard break, events and the tick as one proposal. Canonical step IDs are `state.id + '/step/' + tick`; supply every tick in order. It samples contact once at the first impact tick. The rest of that visual window never grants additional hits.

Only a retained host may publish a plan. Revalidate `expected.melee` and the entire `expected.host` snapshot, plus any external inventory/permission identity, then atomically persist/publish `next` **and all returned characters**. The host context's revision must change with inventory, permission, armour or other relevant external state. Queries are read-only. If a query throws, persistence refuses or a pre-commit observer fails, publish nothing. After publication, presentation errors are committed observer failures; never roll back or replay damage to hide one. `plan.committed` is false until the host makes that publication. Repeated identical commands return their original receipt, without charging, rolling or emitting again. Reusing an ID for another payload refuses.

Pre-impact interruption releases the reservation, spends nothing and enters the declared recovery. Equipment switches are explicit commands; they clear guard/draw/load, interrupt incompatible action state and enforce two hands. Late affordability, ownership, permission or incapacitation failure enters a named free cancellation/recovery without rolling. Post-impact interruption does not refund an already committed impact. Holding an item mesh never creates an active guard or hit.

Guard is an explicit directional approximation: current defender facing cone, relative attack height band, a compatible off-hand shield and enough unreserved stamina. Upkeep is charged per fixed tick, block cost only on a contacting rolled hit. A participant who both attacks and guards retains their attack reservation; unaffordable upkeep/block breaks guard. All participants' combined costs are validated and published together. The large hammer, spear, halberd, bow and crossbow are two-handed in this profile and cannot also use an off-hand shield.

Restore the same sidecar, existing character records and retained physical world before resuming ticks. Persist the actual resolved outcome; do not re-roll it from an animation marker. Bind native visual checkpoint(s) separately. The fixture's `createMeleeYard` demonstrates an atomic synchronous persistence hook, query refusal, post-commit observer errors, mid-action restore and a bounded flat-yard world adapter. Games retain their own cast, inventory, clock, saves and geometry.
