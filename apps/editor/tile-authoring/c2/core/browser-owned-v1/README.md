## Supported source edits and design evaluation

The first-mark command imports the selected ORIGINAL artwork if absent, creates
its explicit target layers and adds its stamp/detail in one canonical command.
Recipe create/clone/revise and preset save use the complete-source validator even
after Artwork/ResourceRefs exist. When marks/layers are unchanged they retain
actual appearance. Old marks, owner pins, unrelated records and geometry remain
exact. Placement/upgrade and combined geometry deliberately refuse until their
separate route is authorized; there is no C1 fallback or empty-source forgery.

Accuracy: this browser profile is preferable for a browser-owned source because
it states the capacities and API logical bytes that can actually be observed,
and excludes unobservable physical reclamation. The strict profile remains
available for its original use case. This is a contract/code judgment, not a
physical memory measurement.

Efficiency: one actual attempt, exact validated-text reuse and actual-store
palette sharing avoid repeated work without raising ceilings. Pure tests measure
reference units and logical JSON flows only; they do not measure frame time,
CPU duration, browser RAM or GPU performance. Prefer this policy provisionally
for the map workshop; real backend timing and peak observations remain required.

Narrative: retaining the selected original stamp/detail and existing painted
surfaces is preferable for the workshop's intended appearance and source editing
experience. This is a subjective product judgment, with original identities,
notices and compatibility profiles preserved. No replacement art is generated.
